## 摘要（结论先行）

1. **A（修优化质量）：P0 六条已办，但"分母是有效上界"这条没修好。** 并入学习策略后，
   越界幅度从 2.079 降到 1.593，但仍有 6/11 个目标越界、385 个(运行×目标)格子里 67 个 >1。
   主结论在两套分母下都是：**胜过随机基线 7/7，胜过最强人工策略 5/7**。
2. **C（反事实）：增长率完全不进策略的观测。** 同一策略在 G=0、0.05、0.10 三个评估情景下，
   全部行为诊断**逐位相同**；增长的唯一效应是把交付建面按机械倍数放大。
   由此推出等待划算的临界条件 `G > 1/γ − 1 = 5.26%`。策略侧的重训未完成（见"未完成"）。
3. **E（外部检验）：v1 写的"14 个真实项目"不成立**（严格判据 4 条、容许命名变体 5 条），
   且两表之间没有空间键，只能做总量节奏比对。比对结果是**模型把立项摊成近乎均匀的节奏，
   真实节奏是尖峰的**；7 个权重档里只有 1 个次序相关显著，**不构成验证通过**。

## 一、A 路线：优化质量

### 1.1 分母改动与残余越界

P0 第 1 条的落地方式不是取全部 rollout 的 max（`scale.py` 的 `_estimate` 文档里说明了
为何不能这么做），而是**把学习策略当作新增的一个"策略"并入同一个估计量**。改动在
`src/tpmorl/rl/scale.py`，产出 `scale_v2/ref_..._R7.csv`。

改完之后的实测（35 次运行 × 11 个目标，归一化值 = 目标值 / 分母）：

| 指标 | 改动前（R6） | 改动后（R7） |
|---|---|---|
| 单次最大越界倍数 | 2.079 | **1.593**（`Aec`） |
| 有越界的目标数 | 2 / 11 | **6 / 11** |
| 越界格子数 | — | **67 / 385** |

越界目标：`Gdp` 1.173、`Eco` 1.380、`Emp` 1.172、`Aec` 1.593、`E2r` 1.586、`Floor` 1.195。

**判断：这一条没通过。** 分母仍不是有效上界，因此"归一化贡献"不能当作"占可达上界的
百分比"来解读，正文里不能出现这种说法（已写入 `可写口径_v1.md`）。

### 1.2 验收结论（R7 分母）

`results_v7/acc_scores_v7.csv`。标量化 = (目标值 / 分母) · 权重向量。

| α | 学习策略 | 随机基线 | 最强人工 | 最强者 | 胜随机 | 胜人工 |
|---|---|---|---|---|---|---|
| 0.00 | 1.577 | −0.664 | 1.342 | eco | ✓ | ✓ |
| 0.15 | 1.387 | −0.436 | 1.181 | eco | ✓ | ✓ |
| 0.30 | 1.322 | −0.208 | 1.085 | big | ✓ | ✓ |
| 0.50 | 1.685 | 0.097 | 1.195 | emp | ✓ | ✓ |
| 0.70 | 1.562 | 0.401 | **1.718** | emp | ✓ | ✗ |
| 0.85 | 2.147 | 0.630 | 2.109 | emp | ✓ | ✓ |
| 1.00 | 2.109 | 0.858 | **2.501** | emp | ✓ | ✗ |

**胜随机 7/7；胜最强人工 5/7。** 输的两档都输给 `emp`（就业导向的人工策略），且都在
偏向就业/建面的高 α 端。这与 v2 在旧分母下得到的 5/7 一致——**结论对分母不敏感**，
可以写进正文，但必须写"与最强人工策略相当或略优"，不能写"全面胜出"。

### 1.3 新发现：`Res` 目标从未生效

35 次运行里 `Res` 恒为 0（最大归一化值 0.000）。这不是越界问题，而是这个目标在当前
奖励实现下**从来没有被触发**。11 个目标里实际起作用的只有 10 个。正文的目标清单必须
据实说明，或先修这个目标再重跑。**这一条 v1/v2 都没发现，列为新的 P0。**

## 二、C 路线：反事实分解（机械效应 vs 策略效应）

### 2.1 结构发现：增长率不进策略视野

查证过程（`src/tpmorl/rl/env_gym.py`）：

* `FAR_GROWTH` 在全文件只出现在**一处**——奖励里的交付建面项：
  `floor += floor_area(...) * (1 + FAR_GROWTH) ** self.t`。
* `self.farcap` 在 `__init__` 里定死，**不随年份变**。
* 策略特征（`pairs()` 的 `N_PAIR_FEAT` 列）里，单元行带的是静态的 `farcap`；
  **时间进度 `t/T` 只出现在「到此为止」那一行**。

**结论：策略既看不到容积率上限在涨，也看不到涨多少。** 它唯一能用的时间信号是
「到此为止」行上的 `t/T` 与预算余额。这是论文时序主张的**结构性限制**，必须写进限定。

### 2.2 机械效应：同一策略跨情景

`results_v7/cf/counterfactual.csv`（35 策略 × 3 评估情景）。自查：`trained_g=0 / eval_g=0`
与 `objectives.csv` 逐位吻合（最大绝对差 0），说明评估器读权重与情景键无误。

跨情景行为差异（`n_initiated`、`first_year`、`last_year`、`mean_year`、`idle_years`）
**最大差全部为 0**。变的只有 Floor：

| 评估增长率 | Floor 倍数（均值） | 范围 | 反解指数 `ln r / ln(1+G)` |
|---|---|---|---|
| G=0.05 | **1.743** | 1.685 – 1.776 | 11.4 |
| G=0.10 | **2.982** | 2.786 – 3.092 | 11.4 |

两档反解出同一个指数 11.4，而立项年均值只有 6.7–7.9（按格数加权 7.02–7.45，
**与按次数加权基本一致，说明并非"大单元晚立项"**）。差额来自奖励那一行的口径：
建面按**建成年**计，建成年 = 立项年 + 建设年限（5 年），11.4 ≈ 7.1 + 4.3（折扣加权后）。

**所以在当前实现下，增长率的全部效应是一个乘性常数，不含任何择时成分。**

### 2.3 由此得到的可检验预测

推迟一年立项：建面涨 `(1+G)`，折扣损失 `γ`（`train_ppo.py` 里 γ=0.95）。等待划算的条件是

```
(1 + G) · γ > 1   ⟺   G > 1/γ − 1 = 5.26%
```

* **G=0.05 落在临界点下方**，模型应当近乎无差异——它是**对照组**，不是效应组。
* **G=0.10 在临界点上方**，若策略有能力择时，等待效应应当在这里出现。

这条预测把"重训能否学会等待"变成一个有方向的检验，而不是碰运气。

### 2.4 未完成

增长组重训（G=0.10 动力学 + 分母锁定在 G=0）**未完成**。为把"增长"与"Floor 被降权"
两个影响拆开，本轮给 `scripts/exp_opt_quality.py` 加了 `--scale-growth`（分母可取自
另一增长率下的参考集），干跑已验证生效并写入日志。正式训练启动后 6.4 小时零完成
（base 组同配置每个运行 29 分钟），沙箱不能列进程也不能发信号，已请用户在终端终止。

## 三、E 路线：外部时序检验

### 3.1 数据审核：作废 v1 的"14 个真实项目"

`results_v7/ext/matched_pairs_audit.csv`。光明区共 8 条计划公告↔规划批准配对，
逐条看名称后：**严格判据干净 4 条**（主体名整段出现在批准名里），
**容许命名变体后 5 条**（"伶伦提可乐旧工业区"对应批准名"伶伦提可乐工业区"）。

v1 写的 14 条来自一个错误的逐字符包含判定（"区"字几乎每个名称都有），
例如「华泰小区更新单元」被同时匹配到三个不相关项目。**v1 该数字作废。**

### 3.2 没有空间键

两表之间没有可用于连接的空间标识，真实项目**无法对到模型的 717 个单元**上。
因此本轮只能做总量层面的节奏比对，做不了逐单元的选址检验。这是数据限制，不是方法选择。

### 3.3 节奏比对结果

真实：光明区逐年计划公告数（2010–2018，9 年）。模型：逐年立项数（跨种子与回合取均值）。
两者各自归一化为份额后比较（`results_v7/ext/tempo_profile.csv`）。**年份对齐是一项假设，
不是数据事实**，必须写进限定。

* **模型剖面近乎均匀**：跨档均值在 0.099–0.120 之间（完全均匀 = 1/9 = 0.111）。
* **真实剖面是尖峰的**：0.029（2013）到 0.265（2010）。
* 次序相关 Spearman 从 −0.211 到 0.796，**7 个权重档里只有 α=0.30 一档达到 p=0.010**。
  7 次检验出 1 个显著，且剖面本身近乎平坦——**这是平剖面上的噪声，不能报作验证通过**。
* **前段份额是唯一稳定的差异**：真实 0.412，模型 0.297–0.361，**7 个档全部低于真实**。
  即模型比现实更不前重。

图：`results_v7/ext/tempo_profile.png`。

### 3.4 与 C 路线的一致性

这两条独立得到的结果互相印证：策略既无信息也无激励去择时（§2.1），
所以立项被预算约束摊平成近乎均匀（§3.3）。**"模型再现了真实的开发时序节奏"这句话
现在有直接反证，不能写。**

## 六、操作教训（写给后续批次）

* **沙箱不能列进程、不能发信号。** 长任务一旦脱离内核启动，就只能等它自己结束。
  以后长批次必须自带上限：在脚本里加单运行墙钟上限与总墙钟上限，超时自杀并落盘部分结果。
* **脱离内核启动不要用 `bash -lc`。** 登录 shell 的 `python3` 不是本环境的解释器
  （实测直接 `ModuleNotFoundError: numpy`）。要用当前解释器的绝对路径。
* **10 路训练会把 12 核占满**，期间任何一行分析代码都要排队数分钟。
  训练期间只做读文件级别的轻活。
