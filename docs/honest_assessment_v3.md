## 二、C 路线：反事实分解（机械效应 vs 策略效应）

### 2.1 结构发现：增长率不进策略视野

查证过程（`src/tpmorl/rl/env_gym.py`）：

* `FAR_GROWTH` 在全文件只出现在**一处**——奖励里的交付建面项：
  `floor += floor_area(...) * (1 + FAR_GROWTH) ** self.t`。
* `self.farcap` 在 `__init__` 里定死，**不随年份变**。
* 策略特征（`pairs()` 的 `N_PAIR_FEAT` 列）里，单元行带的是静态的 `farcap`。

**【2026-09-09 更正】** 本节原写「时间进度 `t/T` 只出现在「到此为止」那一行」，
**该判断错误,作废**。`pairs()` 里 `rows[:n, :N_FEAT] = F[pu]`，而 `obs()` 的
`F[:, 14] = self.t / self.T` 是对**全部单元行**赋值，故每个候选行都带年份。
实测(t=0/3/9/14 单元行 col14 = 0 / 0.2 / 0.6 / 0.9333，与 t/T 逐位吻合)。
错因：我把 `pairs()` 里给 STOP 行**重复**赋 `rows[n, 14]` 的那一行代码，
连同其注释「末行特征只带时间进度与余额」，误读成「只有末行带」。

**更正后的结论（含 2026-09-09 二次更正）**：策略**看得到年份**(`t/T`)、预算余额与单元成本，
并经**候选集收缩**间接感知制度状态（候选行数 1985→1976→1958→1943）。
**但看不到**：容积率上限在涨（`farcap` 定死，四年份均值恒 0.7072）；
自己所处的制度状态与有效期倒计时——`obs()` 虽构造了这两列，
而 `pairs()` 只对**仍可申报**（按定义即"候选"态）的单元建行，故二者在策略输入里
**退化为常量**，实测 15 年全为 0。原写"看得到制度状态、状态内进度"作废。

**这把限制收窄成了一条,而且更可修**：增长只进奖励、不进特征，
所以「涨价能否诱发等待」这个实验**问不出结果不是因为策略没有时间概念**，
而是因为**那个会涨的量对策略不可见**。修法是让 `farcap` 随年份增长，
而不是「把时间放进特征」(时间本来就在)。

**对论文的影响**：策略确实是序贯自适应的，但自适应维度是
**年份 + 资金余额 + 随机演化的候选集**，**不含**显式制度状态。
「不可替代性」只能依赖这一口径；写成"策略观测制度状态"会被查表推翻。

### 2.2 机械效应：同一策略跨情景

`results_v7/cf/counterfactual.csv`（35 策略 × 3 评估情景）。自查：`trained_g=0 / eval_g=0`
与 `objectives.csv` 逐位吻合（最大绝对差 0），说明评估器读权重与情景键无误。

跨情景行为差异（`n_initiated`、`first_year`、`last_year`、`mean_year`、`idle_years`）
**最大差全部为 0**。变的只有 Floor：

| 评估增长率 | Floor 倍数（均值） | 范围 | 反解指数 `ln r / ln(1+G)` |
|---|---|---|---|
| G=0.05 | **1.743** | 1.685 – 1.776 | 11.4 |
| G=0.10 | **2.982** | 2.786 – 3.092 | 11.4 |

两档反解出同一个指数 11.4，而立项年均值只有 6.7–7.9（按格数加权 7.02–7.45，
**与按次数加权基本一致，说明并非"大单元晚立项"**）。差额来自奖励那一行的口径：
建面按**建成年**计，建成年 = 立项年 + 建设年限（5 年），11.4 ≈ 7.1 + 4.3（折扣加权后）。

**所以在当前实现下，增长率的全部效应是一个乘性常数，不含任何择时成分。**

### 2.3 由此得到的可检验预测

推迟一年立项：建面涨 `(1+G)`，折扣损失 `γ`（`train_ppo.py` 里 γ=0.95）。等待划算的条件是

```
(1 + G) · γ > 1   ⟺   G > 1/γ − 1 = 5.26%
```

* **G=0.05 落在临界点下方**，模型应当近乎无差异——它是**对照组**，不是效应组。
* **G=0.10 在临界点上方**，若策略有能力择时，等待效应应当在这里出现。

这条预测把"重训能否学会等待"变成一个有方向的检验，而不是碰运气。

## 三、E 路线：外部时序检验

### 3.1 数据审核：作废 v1 的"14 个真实项目"

`results_v7/ext/matched_pairs_audit.csv`。光明区共 8 条计划公告↔规划批准配对，
逐条看名称后：**严格判据干净 4 条**（主体名整段出现在批准名里），
**容许命名变体后 5 条**（"伶伦提可乐旧工业区"对应批准名"伶伦提可乐工业区"）。

v1 写的 14 条来自一个错误的逐字符包含判定（"区"字几乎每个名称都有），
例如「华泰小区更新单元」被同时匹配到三个不相关项目。**v1 该数字作废。**

### 3.2 没有空间键

两表之间没有可用于连接的空间标识，真实项目**无法对到模型的 717 个单元**上。
因此本轮只能做总量层面的节奏比对，做不了逐单元的选址检验。这是数据限制，不是方法选择。

### 3.3 节奏比对结果

真实：光明区逐年计划公告数（2010–2018，9 年）。模型：逐年立项数（跨种子与回合取均值）。
两者各自归一化为份额后比较（`results_v7/ext/tempo_profile.csv`）。**年份对齐是一项假设，
不是数据事实**，必须写进限定。

* **模型剖面近乎均匀**：跨档均值在 0.099–0.120 之间（完全均匀 = 1/9 = 0.111）。
* **真实剖面是尖峰的**：0.029（2013）到 0.265（2010）。
* 次序相关 Spearman 从 −0.211 到 0.796，**7 个权重档里只有 α=0.30 一档达到 p=0.010**。
  7 次检验出 1 个显著，且剖面本身近乎平坦——**这是平剖面上的噪声，不能报作验证通过**。
* **前段份额是唯一稳定的差异**：真实 0.412，模型 0.297–0.361，**7 个档全部低于真实**。
  即模型比现实更不前重。

图：`results_v7/ext/tempo_profile.png`。

### 3.4 与 C 路线的一致性

这两条独立得到的结果互相印证：策略既无信息也无激励去择时（§2.1），
所以立项被预算约束摊平成近乎均匀（§3.3）。**"模型再现了真实的开发时序节奏"这句话
现在有直接反证，不能写。**

## 六、操作教训（写给后续批次）

* **沙箱不能列进程、不能发信号。** 长任务一旦脱离内核启动，就只能等它自己结束。
  以后长批次必须自带上限：在脚本里加单运行墙钟上限与总墙钟上限，超时自杀并落盘部分结果。
* **脱离内核启动不要用 `bash -lc`。** 登录 shell 的 `python3` 不是本环境的解释器
  （实测直接 `ModuleNotFoundError: numpy`）。要用当前解释器的绝对路径。
* **10 路训练会把 12 核占满**，期间任何一行分析代码都要排队数分钟。
  训练期间只做读文件级别的轻活。
