# 服务器批次 v5 交接单

前置：批次 v4 已跑完但结果不可用于论文，两个缺陷已修（见
[批次v4_查验_v5.md](批次v4_查验_v5.md)）。本批次是修后重跑。

## 一、这次改了什么

| 缺陷 | 改动 | 文件 |
|---|---|---|
| A 分母不可跨机复现 | 参考集挑单元改用 `np.lexsort((目标, 单元, ±成本))` 确定性次键；`REF_VER` R4→R5 | `src/tpmorl/rl/scale.py` |
| B 冷却期 0/1 等价 | 本步新进入冷却期的单元不参与步末 `clock += 1` | `src/tpmorl/env/schedule.py` |

本机已验证：

- 排序键 (成本, 单元, 目标) 在 1985 个候选上**唯一**，顺序完全确定，无残留并列
- 冷却期 0/1/2/3 → 过期后第 1/2/3/4 年可再立项，四档各不相同
- 六份 R5 参考集 md5 互不相同；八个策略行在每对相邻冷却期档间均有差异

## 二、一处语义变化，必须知道

修缺陷 B 使**生效冷却期等于设定值本身**，而此前生效值是 `max(设定, 1)`。
所以基线组（冷却期 2）也比 v4 严格了一年——**v4 的全部六组结果都不能与 v5 混用**，
包括基线组。v4 产出保留在 `exp_v4/`、`results_v4/` 作为缺陷记录，不删。

## 三、怎么跑

脚本无需改动，只把输出目录换掉，避免覆盖 v4：

```bash
cd TP-MORL && git pull
BASE=data/processed/gm_dataset_v1/exp_v5 \
RES=results_v5 \
bash scripts/run_batch_v5.sh
```

情景分组、每组规模（7 权重档 × 5 种子）、`--iters 400 --eps 8` 与 v4 完全一致，
六组各 36–45 分钟，全批约 4 小时。

## 四、跑完请自查三条

1. `results_v5/STATUS.md` 是否 6/6 成功，标签 `batch-v5-complete` 是否已打
2. 六组日志里的情景键是否互不相同，且都带 `_R5`（带 `_R4` 说明拉到的是旧代码）
3. 第 2 组（冷却期 0 档）与第 4 组（1 档）的 `objectives.csv` 是否**不再相同**
   —— 这是缺陷 B 修好的直接证据，若仍相同请立刻停下并报告
