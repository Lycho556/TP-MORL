# P1 服务器实验说明

## 1. 需要同步到服务器的文件
在本机仓库根目录执行（只提交 P1 相关文件，不动其他未提交改动）：
```bash
cd ~/Desktop/TP-MORL
git add src/tpmorl/env/opportunity.py src/tpmorl/rl/env_gym.py src/tpmorl/rl/scenario.py \
        scripts/p1_common.py scripts/p1_fqi_job.py scripts/p1_rolling_horizon.py \
        scripts/p1_spatial.py scripts/p1_collect.py scripts/exp_fqi_local.py \
        data/processed/gm_dataset_v1/metro 启动实验_P1服务器.sh docs/P1服务器说明.md \
        results_p1/rolling results_p1/spatial
git commit -m "P1: rolling-horizon baseline, metro infrastructure field, spatial analysis, server job package"
git push
```
`scripts/exp_fqi_local.py` 必须一起提交：`p1_fqi_job.py` 从它导入 `make_trees`，而已提交的旧版把 `n_jobs=-1` 写死、不读 `TPMORL_NJOBS`——服务器会拿到旧版，每个作业开满全部核且结果不再逐位可复现，复现作业必然失败。

源码改动是**加法**：默认 `INFRA_MODE="cluster"`，主配置逐位复现（参考值 6876.246054424286、持续贪心 0.7745224826431258、轨迹贪心 0.8935554552319573、FQI 种子 0 为 0.9095038725980372）。启动脚本先**逐位**自检前三个数（环境、oracle、规则基线），不一致就中止。FQI 种子 0 只做**容差**检查（默认 |Δ| ≤ 0.01，可用 `P1_REPRO_TOL` 覆盖）：ExtraTrees 训练跨平台（本地 arm64 / 服务器 x86_64）与跨 sklearn 版本不逐位一致，2026-10-02 服务器（sklearn 1.7.2）实测 0.9091809875451883，差 3.2e-4，约为种子间标准差的 3%。因此 **P1 的全部 FQI 数字以服务器这一个环境为准，组内可比**；与论文主表（本地环境）并列时须注明来源。

## 2. 服务器上运行
```bash
cd ~/TP-MORL && git pull
conda activate <你的环境>          # 需 numpy/pandas/scipy/scikit-learn/torch/joblib
nohup bash 启动实验_P1服务器.sh > ~/p1.log 2>&1 &
tail -f ~/p1.log                   # 看进度；每个作业结束会打印 OK/FAIL
```
常用选项：
- `NPROC=16`：并行作业数（默认 CPU 核数 − 2，上限 32）
- `JOB_GROUPS="main noconf"`：只跑部分组
- `FORCE=1`：忽略已有结果重跑（默认断点续跑）
- `PUSH_EACH=0`：关闭逐作业提交（**默认开**：每个作业一结束就 commit + push 自己的 CSV、schedule 与状态行，备注带各规则 ratio 摘要；失败作业的日志尾部进 `results_p1/fqi_runs/<批次>/fail_logs/`）
- `AUTO_COMMIT=0`：关闭收尾汇总提交（**默认开**；全部成功时另打标签 `p1-complete-<批次>`）
- `NO_PUSH=1`：只 commit 不 push

逐作业提交在 32 路并行下用 `flock` 串行化 git 操作；推送以 SHA 比对确认落地，被拒则 rebase 重推。**跑批期间不要往 main 推 `src/` 或 `scripts/` 的改动**——rebase 会把新代码带进服务器工作区，后续作业将用新代码运行；脚本检测到这种情况会在 STATUS 里告警。

## 3. 作业组（共 70 个作业）
| 组 | 内容 | 作业数 | 单个耗时（本机实测/估计） |
|---|---|---|---|
| main | 主配置 FQI，初筛 M = 10/20/50/全部 × 训练种子 0–4；每个模型在列表种子 7,0,1,2,3,4 上评估，并跑监督评分器与随机基准 | 20 | M=20 约 5 分钟；M=0 约 15–40 分钟 |
| noconf | 去掉符合性闸门后**所有规则重跑**（FQI 在新价值表上重训） | 5 | 约 5.5 分钟 |
| metro | 地铁 6 号线、6 号线支线、13 号线北延的实测站点与开通年份构成基础设施场 | 10 | M=20 约 5.5 分钟；M=0 更长 |
| oos | 样本外：在主场训练，在场种子 1–5 上直接评估；并在每个场上各自重训一次作对照 | 5 | 约 30 分钟 |
| variant | 六个场变体，单线程确定性重跑 | 30 | 约 5 分钟 |

每个作业单线程、峰值内存低于 1.2 GB。总计约 6–10 CPU 小时，16 核并行约 1 小时。

## 4. 发回结果
把 `results_p1/fqi/` 整个目录发回（或 push 后告诉我 commit 号）。其中：
- `summary_by_config.csv`：每个配置 × 规则的均值、标准差和范围，分别按默认列表种子 7 和全部列表种子统计；
- `summary_oos.csv`：样本外与样本内对照；
- 每个作业的原始 CSV、`results_p1/fqi_runs/<批次>/STATUS.md`（逐作业状态表）与收尾时复制进来的 `STATUS.txt`、`summary.txt`。（`logs/` 在 `.gitignore` 里，不入库。）
