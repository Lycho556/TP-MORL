# 服务器批次 v11 交接单

**v7–v10 的服务器批次不存在**（v7 之后的实验都在本地小规模跑，用于诊断）。
v11 是 P0-1「情景无关固定分母」落地后的第一个完整批次，**取代 v6 作为论文主结果来源**。

## 一句话：v11 跟 v6 有什么不一样

| | v6 | v11 |
|---|---|---|
| 分母 | 每个情景各自估一套 | **全组统一固定分母** `--fixed-scale 0,0.1` |
| 增长率 | 未作为实验维度 | 第 1、2 组构成 g=0 / g=0.1 反事实臂，**标量化回报可直接比** |
| 折现率 γ | 硬编码 0.95，不可改 | 新增 `--gamma`，第 7、8 组扫 0.90 / 0.926 |
| 规划期 T | 固定 15 | 第 9 组延长到 20，直接检验零梯度盲区假说 |
| 标注 | 只在全批结束打一个标签 | **每组跑完单独打标签** `v11-g{N}-{名}` |

每组 7 权重档 × 5 种子 = 35 次运行，`--iters 400 --eps 8`。

## 跑法

```bash
cd TP-MORL && git pull

# 先干跑 3 分钟，确认管线通（不提交、不打标签）
PUSH=0 ITERS=2 EPS=1 BASE=/tmp/dry11 RES=/tmp/dry11res \
    bash scripts/run_batch_v11.sh 1 7

# 正式跑：全九组
nohup bash scripts/run_batch_v11.sh > results_v11/batch.log 2>&1 &

# 也可以只跑指定组
bash scripts/run_batch_v11.sh 7 8 9
```

预计 128 核约 6–9 小时（v6 六组约 4 小时，v11 是九组）。

## 自动上传与标注的机制

**每一组跑完立刻做三件事，中途断掉不丢已完成的组：**

1. `git add -A && git commit`，提交信息含组号、组名、状态、耗时
2. `git push origin HEAD:main`，失败自动 `pull --rebase` 后重试三次
3. **单独打标签** `v11-g{N}-{目录名}` 并推送，例如 `v11-g7-gamma090`

全九组成功后再打 `batch-v11-complete`。任一组失败则**不打**完成标签，
但失败不终止整批——记为 FAIL 继续下一组。

运行状态实时写在 `results_v11/STATUS.md`，每组结束刷新一次，GitHub 上直接可读。

## 服务器可自查的四条

1. **分母键必须互不相同**，且都以 `_R7` 结尾：
   `grep -h "已写出\|情景" results_v11/g*.log`
   出现 `_R6` 说明 `git pull` 没生效。
2. **第 7、8 组的键必须带 γ 后缀**（`T15G09` / `T15G0926`）。
   不带说明 `--gamma` 没生效，这两组等于白跑第 1 组。
3. **第 1 组与第 2 组的固定分母必须完全相同**（这正是 P0-1 的目的）。
   不同则固定分母没生效，两臂又不可比了。
4. **第 1 组与第 3 组的 `objectives.csv` 必须不同**。逐位相同即为制度参数改动未生效，
   停下来报回。

## 结果怎么比 —— 这条最容易搞错

固定分母只消除了**增长率**这一维。制度参数（有效期、冷却期、建设年限、折现率、
规划期）**仍然进分母缓存键**，因为它们改变可达上界。所以：

- **第 1 组 vs 第 2 组**：标量化回报可直接比。这是唯一一对可以比总分的。
- **第 3–9 组 vs 主组**：**只能比 `objectives.csv` 的原始量纲值**（交付建面平方米、
  成本、立项年份分布），**不能比标量化回报**。

另外第 7、8、9 组的 γ / T 是新键，没有对应的学习策略参考表，分母是**第 0 轮**
（仅由人工参考集决定），而第 1–6 组是**第 1 轮**（并入了学习策略）。这又是一层
不可比。写论文时这三组只作敏感性方向的定性陈述。

## 已知且不需报的现象

- 八个正向目标的**分母数值在 base/relax2/relax5 三组间相同**。v6 已逐行核对：
  45 条参考策略里 34 条数值不同，只是取到最大值的那条策略从不让计划失效、
  不受冷却期影响，差异落在 `Disrupt` 与 `Expire` 列。不是缓存串组。
- 部分种子会出现 `立项=0`（模型学到全程不动）。α=1.0 档偶发，属正常探索结果。

## 待办：这批跑完之后要做的事

第 9 组（T=20）是判据。如果晚期立项占比从 36–48% 显著下降，
就证实了「只认竣工才给分」造成零梯度盲区，那么下一步是改记分方式
（批准阶段给一部分分、竣工给剩下的），而不是继续加训练量。详见
`docs/打分方式_实务贴合度评估.md` 第三节。
