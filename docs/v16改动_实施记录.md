# v16 改动实施记录

**起因**：v15 前 8 组验收（`docs/验收_v15前8组.md`）判定主判据不成立，且给出了原因——
窗外立项率 LSR 的可动空间被年度预算压到只有 2–3 个百分点。两条改动由此而来，
外加用户提出的一条建模质疑（每格转换成本不该一刀切）。

---

## 一、撤回的判断

v15 的主判据"补齐 6 维生命周期观测后 LSR 下降、CRH 上升"**作废**。
不是因为没做出来，而是因为**这个判据在 budget=900 下不可能被任何策略改善**：
窗内立项数被"年度额度 / 单元均价"硬顶（实测 6.8 个），而立项总数约 21.7 个，
LSR 的下限就是 0.686，实测 0.718。同时 LSR 作为**占比**还有一个反常性质——
放宽预算会让立项总数上升、窗内立项位仍被配额顶住，**LSR 反而变差**。
故 LSR 不是一个可优化量，v15 拿它当主判据是设计错误。

---

## 二、改动 A：主判据换成"窗内立项位占用率"

`eval/metrics.py` 的实施类指标新增五项（逐组与逐运行两张表都会带）：

| 字段 | 含义 |
|---|---|
| `n_init_early` | 前 y0 年（含）的立项数／回合，y0 由情景推出而非写死 |
| `cap_early_quota` | 配额给出的窗内立项位上限 = y0 × quota |
| `cap_early_money` | 资金给出的上限 = y0 × budget / 本组实测单元均价 |
| `early_fill` | **新主判据** = `n_init_early / min(两个上限)` |
| `early_binding` | 当前情景的瓶颈是"配额"还是"资金" |
| `LSR_floor` / `LSR_excess` | LSR 的结构下限与超出量，旧判据只报超出量 |

`ScenarioSpec` 随之新增 `quota` 字段，`scripts/eval_metrics.py` 从 `diag.quota_eff`
读**生效值**（与 `hazard_eff` 同理：扫配额那几组若按默认 3 算，占用率的分母就错了），
并把来源记进 `prov`。

在 v15 前 8 组上回算的结果：**8 组全部 `early_binding = 资金`**，
`early_fill` 0.83–1.01。这直接证明 v15 那批测不出观测的作用，不是策略不行。

## 三、改动 B：主组年度总额 900 → 2700

900 是情景参数（依据表原文："必须扫；代码注释明确不是标定值"），可以动。
选 2700 的三条理由：

1. **让瓶颈从资金交给配额**。单元中位成本 550、实测均价 661；2700 下窗内五年
   资金可支持 24.5 个 > 配额上限 15 个，于是策略第一次面对"该选哪 3 个"
   而不是"还剩不剩钱"。启动脚本的自检 (l) 把这条写成硬断言——若不成立当场停批，
   否则整批仍在测 v15 已证明测不出来的东西。
2. **消掉大单元的畸变**。最贵单元 2610 < 2700，单年即可承担，不再需要靠攒 3 年结转。
3. 900 与 1500 保留为对照档（第 3、4、7 组），故新旧结果仍可比。

第 3、4 组是 v15 主组／消融组的**同参重跑**，与第 1、2 组构成
"钱紧／钱松 × 观测开／关"的 2×2 交互检验——这是本批的核心科学载荷：
若 6 维观测的效应**只在钱松时出现**，就等于用实验证明了"钱是瓶颈、信息不是"。

## 四、改动 C：拆除基数按现状用地类别（用户提出）

**原状**：成本 = (每格 50 + CCM[现状,目标]) × 格数。CCM 确实按"转成什么"区分
（0–100，非对称），但实测拆除基数占单元总成本**中位 62%**，即类型差异只解释 38%，
而占主导的那 62% 对"拆的是什么"完全不敏感——拆一格城中村与清一格农地同价。

**改法**（`reward.CELL_COST_MULT` + `cell_base_vector`，新开关 `--cell-cost-mode`）：
基数按**被拆除的现状类别**取值，倍率依补偿对象的强弱排序
（住宅 > 商业 > 公用设施 > 工业 > 农地 > 生态绿地）。
gm_dataset_v1 上现算：A 25.17 · I1 50.34 · I2 45.31 · C 90.62 · R1 100.69 · R2 120.83
——**拆一格城中村 ≈ 清 4.8 格农地**。

两条设计要点，都是为了让这一档可解释：

- **均值保持**。倍率按候选池现状用地格数加权归一，使 `Σ基数×格数` 与 flat 档
  **逐位相等**（实测 377650.0 = 377650.0）。不做归一的话，bytype 同时改变了成本
  水平与成本结构，而分母、预算咬合、可达上界全对成本水平敏感，两个效应无法分离。
  归一系数由数据现算、不硬写——候选池构成随数据集版本变，硬写会静默失配。
- **两条成本路径读同一个向量**。基数向量由 env 建好 hist0 后写入 `Reward.cell_base`，
  `PC`（预算路径）与 `convert_cost`（Cost 目标路径）共用它，并在 env 构造时断言
  两者相等。v1 的缺陷正是 `CELL_COST` 只进了预算路径、漏了 Cost 目标。

**口径声明**：倍率是**假设，不是标定值**。单元表 `gm_renewal_units.csv` 无投资额／
补偿额字段，开放平台亦无逐类补偿标准数据集，故只能给相对倍率并作情景参数报告。
论文里必须与"通道分档建设年限"同等处理——写成敏感性情景，不得写成实证依据。

`cell_cost_mode` 已入分母缓存键（`KB`），flat 档键与既有缓存逐字不变。

## 六之二、干跑当场推翻了一条设计，已在开跑前改掉

第一版 v16 组表把 `budget4500` 排在第 8 组，主组定 2700/配额 3。干跑（`ITERS=2`）
的落盘值立刻否掉了这个安排：

| 组 | `early_fill` | 瓶颈 |
|---|---|---|
| main（2700, 配额 3） | **0.987** | 配额 |
| ablation | 0.964 | 配额 |
| bytype | 0.977 | 配额 |
| quota6（2700, 配额 6） | **0.833** | 资金 |

**窗内占用率在配额 3 上同样饱和**——2700 下连只训练了 2 轮、近乎随机的策略都能把
窗内 15 个立项位填到 99%。于是新主判据在主组上**也没有活动空间**，与 v15 的 LSR
是同一个病：判据被制度上限顶死，与策略好坏无关。

改动（开跑前）：第 5、6 组换成 `richQ6 / richQ6Abl`（2700 + 配额 6 + 观测开／关），
这是唯一实测仍有余量的一档（0.833）；`budget4500` 删除——它只会让占用率更饱和。
现在批次含**两个** 2×2：钱紧／钱松 × 观测开／关，以及配额紧／松 × 观测开／关。

同时新增两个不受配额顶死的判据（`CRH_T_early`、`slack_mean_early`，只看窗内那批单元）。
但要如实记下：干跑里 `CRH_T_early` 五组全部约 0.693，**也接近常数**——窗内立项的单元
一旦立了，成败几乎只由审批随机性决定（无条件失效率 0.294，1−0.294 = 0.706）。
`slack_mean_early ≈ +2.67`（窗内立项确实来得及）而全期 `slack_mean ≈ −2.3`。

**这串数字连起来是一个实质结论，不是技术故障**：在光明区的标定参数下，
**时序维度上几乎没有决策余量**——钱紧时节奏由资金定，钱松时节奏由配额定，
两头都不由策略定；剩下的真实自由度在**选哪些单元、转成什么功能**（空间目标之间的权衡），
而不是在什么时候立项。论文的主张应当据此重写，不要再把"更会择时"当卖点。


1. `CRH_Teval` 在 26 年口径下退化成常数（8 组全部 0.705983 = 1 − 无条件失效率），
   与策略无关。应只报 15 年口径，26 年口径移附录并注明退化。
2. `staged` 组 `idle_ratio` 为负（承诺口径下可再承诺释放额度），该档不应报此指标。
3. 基线自检 (b)「greedy_crh 期内完工 ≥ myopic」比的是绝对个数，而两者立项数差近 3 倍，
   判据写法本身不对，应改为比完成率。
4. `greedy_crh` 与 `frontload` 在当前设定下退化为同一策略（11 个目标逐位相同），
   应合并或重新定义贪心规则。
