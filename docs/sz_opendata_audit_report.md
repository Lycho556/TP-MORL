# 深圳市政府数据开放平台 — 订阅需求核查报告

**核查方式**：平台目录接口全量抓取（数据集 4841 条 = 市级 1977 + 区级 2864；数据接口 3469 条 = 市级 1798 + 区级 1671），并对 30 余个关键条目逐个调用字段元数据接口核实字段清单。**证据等级：已核实平台实际条目与字段**，非关键词推测。

**你提供的 appKey 状态**：有效。接口返回"未经许可的证书，请先订阅接口"（错误码 10001）而非证书无效，说明认证通过、只是尚未订阅具体接口。**建议核查完毕后在平台重置该 key**，它已在对话中明文出现过。

## 一、结论速览

21 项需求中：满足 5 项、部分满足 10 项、不满足 6 项（其中 2 项为决定性缺失）。

**平台能解决的**：法定时序的"事件清单"（更新单元计划、土地整备、建设用地规划许可证含发证日期）、需求侧人口（街道级模型化数据，质量意外地高）、保障房状态与批次、企业-楼栋关联。

**平台解决不了的四件事**——这决定了项目的技术路线：

1. **全平台没有空间几何**。4841 条中标题含空间语义的仅 16 条，且均为医保药品目录、气象格点、码头坐标一类，与规划要素无关。逐个核查的地块、建筑、绿地、更新单元数据集**全部没有坐标或边界字段**，位置一律是文本地址（"用地位置""位置描述"）。→ 地块级动作空间无法从平台构建，必须另找矢量来源或做地址地理编码。
2. **没有建筑建成年份（除福田区）**。市级『建筑物数据』6898 条只有三个字段：建筑物编码、名称、地址。全市唯一带年份的是『福田区-建筑物信息』17124 条（竣工时间、建筑高度、建筑用途分类、耐火等级），但 2023-02 后未更新。**光明区没有任何建筑年份数据**。
3. **没有计划有效期起止、延期、失效记录**。这是层面2动作掩码的核心字段。平台上最接近的是坪山区『已批城市更新单元计划』的"批次"字段与『已批单元规划』的"审批年度"——只能得到粗粒度时间轴，无法还原"某单元在第 t 年是否处于有效期内"。
4. **服务设施与交通没有坐标**。教育机构信息只有编号/名称/地址；卫健委的 13 万条是行政许可流水而非机构名录；公交站点与线路、道路中心线、行政区划边界均无。平台上带经纬度的基本只有气象自动站。

## 二、需要修正的一个前期判断：光明区不是最佳选区

这是本轮最重要的意外发现。按平台实际数据质量排序：

| 区 | 更新数据 | 字段质量 | 时间维 |
|---|---|---|---|
| **坪山区** | 已批更新单元计划 **117 条** + 已批单元规划 39 条 | 街道、更新单元名称、申报主体、拆除范围用地面积、**批次**、更新方向；规划表另有开发建设用地、计容积率建筑面积、**审批年度** | 批次 + 审批年度 |
| 龙岗区 | 更新单元计划 + 拆除范围实施主体确认 + 历史违建权利人核实 + **年度土地整备计划 588 条** | 更新计划表未公开字段元数据（仅文件） | 年度整备计划有年份 |
| 福田区 | 更新单元计划审查 2 条 | 但**建筑物信息 17124 条含竣工时间**，全市唯一 | 建筑竣工时间 |
| **光明区** | 城市更新项目 **仅 14 条** | **仅 3 字段**：项目名称、街道、拆除范围用地面积 | **无任何时间字段** |

光明区在土地整备方向数据尚可（整备项目 45 条、利益统筹 18 条、房屋征收 6+5 条），但**城市更新方向的平台数据几乎不可用于建模**。坪山区的"批次 + 更新方向 + 审批年度"是全市唯一能直接支撑多期时序建模的结构化字段组合。

**建议**：把主案例区从光明区改为**坪山区**，或采用"坪山区做方法验证 + 光明区做土地整备方向的对照"。这个改动需要你确认——它会影响你和当地的对接关系，平台数据质量只是一个维度。

## 三、平台的两种获取方式（订阅时要分清）

- **文件下载**：需登录且完成实名认证。市级『城市更新单元计划』(742 条)、『城市更新单元规划批准基本情况』(271 条)、街道级人口数据、龙岗区更新单元计划均**只有文件下载，没有接口**。
- **数据接口**：用 appKey 调用，但**须逐个接口订阅**。3469 个接口中，坪山已批计划、光明更新项目、福田建筑物、建设用地规划许可证、地铁站点、商事主体房屋编码、政府保障房房屋基本信息均可订阅。

`sz_opendata_requirement_audit.csv` 的"推荐订阅"列给出了每项的 resId 与获取方式。

**特别注意**：『城市更新单元规划批准基本情况』(29200/00303518) 的文件是**按时段切分**的——2018.01-2019.11、2019.12-2020.11、2020.12-2021.11……这是平台上唯一按时间组织的更新数据，虽然是"已批规划"而非"计划有效期"，但它给了每个单元进入"已批"状态的时间窗口。**这份文件对层面2的价值最高，请优先下载全部分期文件。**

## 四、必须从平台外补的数据

| 缺口 | 替代来源 |
|---|---|
| 地块/更新单元边界矢量 | 各区"城市更新一张图"逐个导出；法定图则公示图矢量化；国土三调（需申请） |
| 计划有效期、延期、失效 | 各区政府门户的计划公告及附件（已确认存在，需手动下载，解析脚本已就绪） |
| 建筑年龄（光明/坪山） | 遥感影像变化检测反推；或改用"更新单元获批时间"作为间接代理 |
| 学校/医院/公园/公交坐标 | 高德或百度 POI；OSM |
| 道路中心线、行政边界 | OSM；民政区划数据 |
| 地铁开通日期 | 各期线路通车时间表，手工整理，条目不多 |

## 五、建议的下一步

1. **你确认选区**：坪山区（数据最优）还是坚持光明区（需接受时间维要全部从区政府公告手工补齐）。
2. **优先下载三份文件**（需你登录）：市级『城市更新单元计划』742 条、『城市更新单元规划批准基本情况』全部分期文件、街道级人口归属数据。下载后发我，我验证真实列名并接入解析脚本。
3. **优先订阅四个接口**：坪山已批更新单元计划、建设用地规划许可证、福田建筑物信息（若选福田做建筑年龄验证）、政府保障房房屋基本信息。
4. **空间几何另起一条线**：这是目前最大的单点风险。建议先花半天确认各区"城市更新一张图"能否批量导出，再决定动作空间是落在地块还是落在更新单元。
