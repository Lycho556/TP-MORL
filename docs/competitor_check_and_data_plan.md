## 2. LUP-PPO：时间维未占位，但生态位重叠——这是本课题最需要正面处理的一篇

**DOI**：10.6084/m9.figshare.32524416（v2，CC-BY，figshare software 类型；landing: figshare.com/articles/software/LUP-PPO.../32524416）

### 2.1 它做了什么（据完整摘要）
- 任务：**地块级（parcel-level）土地利用优化**，面向精细化城市治理与宜居社区，目标是在经济发展、生态保护、社会公平之间取得动态平衡。
- 方法两点：①改进的 **PPO** 网络结构，用**共享残差块**捕捉更深层的建成环境内在特征以增强状态表示；②**自适应双目标加权**，把"最优用地配置"的知识迁移过来，在异质规划情境下自适应调节**用地强度**与**居民可达性**之间的权衡。
- 自述缺口（与我们此前记录一致）：现有RL模型受限于缺少规划理论约束与可迁移知识，难以表达复杂规划情境、难以形成自适应多目标。

### 2.2 **关键发现：案例区就在深圳**
> 在中国深圳的**两个街道级社区（华强北、东门）**上验证，两地功能发展特征差异明显。

这意味着：
- **"深圳 + 已建成高密度社区 + 地块级RL用地优化"这个生态位已被占据**，且华强北、东门恰恰是深圳建成度最高、约束最琐碎的区域——与你原本设想的命题正面重叠。
- 但它是**单期静态优化**：摘要中的"dynamic"指的是①episode内用地分配的序贯决定与动力学，②多目标之间的动态平衡；**没有任何日历时间、分期实施、资格窗口、延期/失效的语义**。
- 因此**你的差异化必须收紧到时间维本身**，而不能停留在"地块级 + 深圳 + 已建成区"。建议的表述方向：LUP-PPO 回答"这片地最终应该是什么功能"，本课题回答"**在法定时序约束下，哪一块地在哪一年可以动、动成什么**"。
- 附带好处：LUP-PPO 是 CC-BY 且 figshare 类型标为 software——**很可能附带可复用代码**，是理想的基线实现。（figshare API 与站点在沙箱内均返回 403，需你在浏览器下载文件包。）

## 3. SCS 2026 "Graph Neural Network Actor-Critic ... Parcel-Based Land Use Allocation"

**DOI**：10.1016/j.scs.2026.107421｜2026年7月｜作者：Sahebgharani, Wiśniewski, Dulebenets｜**闭源**（OpenAlex oa_status=closed；Crossref 与 Semantic Scholar 均无摘要；Unpaywall 未查询）

**无法确证，只能给推断**。第一作者的研究谱系清楚地指向**单期静态几何优化**：
- 2015–2016：NSGA-II、并行粒子群、混合元启发式做多目标土地利用分配；
- 2024（ISPRS IJGI, doi:10.3390/ijgi13070224）：**双层**街网与用地细分设计优化，用遗传算法解街道设计、模因-遗传算法解用地细分，目标是最小化地块面积偏离标准值、最小化道路占地，明确面向**不规则街区**与**不同规模地块**——是纯静态数学规划；
- 另有大量可达性、城市洪涝下路网韧性/脆弱性研究 → 解释了 SCS 2026 标题里的 "resilient"，很可能是**韧性目标项**（如洪涝或冲击下的服务可达性保持），而非时间维。

**判断**：SCS 2026 大概率是把他 2024 双层静态模型换成 GNN+Actor-Critic 求解器，仍为单期分配，"resilient" 指目标函数而非动态过程。**但这是推断，不是核实**——需拿到全文确认。若你有 ScienceDirect 机构权限，请下载 PDF 给我，我核对其 MDP 定义中是否存在 decision epoch / period 概念。

## 4. 深圳市政府数据开放平台：不可程序化访问

- 你给出的 `opendata.sz.gov.cn/maintenance/personal/toSubscribe` 是**个人中心的"我的订阅"页**，需登录后才有内容，本身不是数据目录。
- 已获授权访问 `opendata.sz.gov.cn` 后，实测首页、数据集详情页（`/data/dataSet/toDataDetails/...`）、接口详情页（`/data/api/toApiDetails/...`）**全部返回站点自身的 403 拦截页**（非允许清单拦截）。这与各区政府门户（szgm.gov.cn 等）返回"当前访问疑似攻击行为"是同一类站点侧防护。**不采取伪装客户端标识等绕过手段。**
- 因此平台侧只能由你在浏览器中操作。平台机制要点（据检索）：数据以**数据集下载 + 数据接口（API）**两种形态提供，接口调用需在平台注册并**申请授权/申请密钥**（平台设有"数据申请"与"需求征集"入口）；未见"城市更新单元"专题数据集，但**"建筑物数据"属平台热门数据集**——这是层面1最关键的候选源。

**请你在浏览器中优先确认三件事**：
1. "建筑物数据"数据集/接口的**字段清单里是否含建成年份（或竣工时间、房屋年代）**；若含，则层面1的建筑年龄变量可直接取得，否则退回到 2018 年建筑物普查数据。
2. 该数据集是否可**按行政区筛选**（光明区、龙岗区）并整区导出。
3. 若仅提供 API：申请密钥后把**接口地址 + 参数说明 + 密钥**给我（密钥请单独提供，我不会写入任何产物），我来做批量拉取与整区拼接。

## 5. 光明 / 龙岗数据处理：脚手架已备，等文件即可开跑

无法自动抓取，但我已把"拿到附件后立刻能跑"的部分做完了，见 `renewal_unit_ingest.py`。它做三件事：
1. **统一模式**：把各区格式不一的《城市更新单元计划一览表》归一到同一张宽表（`units`）；
2. **事件化**：把计划公告 / 设定有效期 / 延期调整 / 失效 / 规划批复各类公告归一为长表 `events`（unit_id, event_type, event_date, valid_from, valid_to, 字段变更前后值），这就是层面2动作掩码与层面1状态演化的数据底座；
