# 重跑清单 v2（奖励口径修补后）

**为什么必须重跑：** 两处改动都改变了奖励本身，不只是后处理。

1. `Cost` 目标此前漏掉拆除补偿基数（`CELL_COST`），使 18.2% 的动作（纯自
   转换）在目标上完全免费。见 `docs/reward_defect_v1.md` §7.1。
2. 目标归一分母改为在实际约束情景下由手工参考集构建，且估计量换成
   「先按策略对种子取均值、再跨策略取上界」。见 §7.2–7.3。

**因此作废：** `docs/reward_defect_v1.md` §5 的全部数值结果、所有
`curves.csv` / `learning_curves.csv` / `最终回报` / `pareto_front.csv`。
**仍然成立：** §5.1 的方法论结论（`Floor` 落后不是欠收敛导致），
`objectives.csv` 的原始量纲值可用于跨情景对照但需按新奖励重算。

## 步骤

1. 取代码：`git clone` 后 `git log -1` 应看到「修补 Cost 目标漏项」这条提交。
   数据集（4.6M）随仓库一起来，无需额外传输。
2. 建环境：`torch`、`numpy`、`pandas`、`matplotlib`。所有命令需
   `PYTHONPATH=src`；并行时设 `OMP_NUM_THREADS=1`（否则 torch 线程与进程池
   争核，实测拖慢数倍）。
3. **删除修补前的分母缓存**：`data/processed/gm_dataset_v1/scale_v2/` 下
   `ref_*.csv` 若早于本次提交，必须删掉重建，否则沿用错误口径。
4. 重建分母并核对：

   ```
   PYTHONPATH=src OMP_NUM_THREADS=1 python3 -m tpmorl.rl.scale \
       --budget 900 --carry 3 --growth 0
   ```

   验收：打印的「旧/新」列中 `Eco` 应为 10.85、`Cost` 应为 0.67
   （见 §7.3 的表）。数字不符说明奖励或参考集与本次提交不一致，先查这一步。
5. 主扫描（35 个作业 = 7 个权重档 × 5 个种子）：

   ```
   PYTHONPATH=src OMP_NUM_THREADS=1 python3 scripts/exp_opt_quality.py \
       --out data/processed/gm_dataset_v1/exp_opt_v2 \
       --iters 400 --eps 8 --workers <核数>
   ```

   本机 10 并行耗时 174 分钟；进度输出被管道缓冲，**不要**用 `grep`/`tee`
   过滤，否则看不到进度。分母已在主进程预先构建，worker 不会竞争写入。
6. 产出：`objectives.csv`（11 维目标，原始量纲）、`curves.csv`、
   `pareto_front.csv`、`runs.json`。

## 验收基准

跑完先做这三项判定，任一不符即为异常，先查不要继续解读：

| 判定 | 期望 |
|---|---|
| `small`（买最便宜）类行为的 `Cost` | 非零。若为 0 说明第 3 步的缓存没删干净 |
| α≥0.5 的训练回报 | 应为正，且明显高于 0（手工「买最大」基线 +0.358/+0.656） |
| α=0 的训练回报 | 可能仍 ≤0——这是**已知**未解决问题（§7.5），不是训练失败 |

手工策略基线（8 种子均值，同情景），用来判断 RL 是否学到东西：

| α | 0.00 | 0.50 | 1.00 |
|---|---|---|---|
| 买最大 | −0.043 | +0.358 | +0.656 |
| 随机填满 | −0.576 | −0.038 | +0.362 |
| 买最便宜 | −0.132 | −0.073 | −0.030 |
| 完全不动 | 0.000 | 0.000 | 0.000 |

**RL 若在某档低于「买最大」，说明尚未超过一行启发式**——这是本项目当前的
真实门槛，`Floor` 单项上 RL 此前是输给随机基线的（§7.4）。

## 跑完后必须回答的问题（按优先级）

1. RL 在 α≥0.5 是否超过「买最大」基线？未超过则先查收敛，不要解读前沿。
2. α ≲ 0.3 的不作为吸引子是否仍在？§4 列出的两个竞争解释仍未区分：
   生态收益（新建绿地、能效提升）在目标集中是否表示不足。
3. `Floor` 单项对 `eval_random` 的劣势是否随新奖励消失。

## 注意

- **跨情景（不同 `--budget`/`--carry`/`--growth`）的标量化回报不可比**，分母
  按情景而异。跨情景只能比 `objectives.csv` 的原始量纲值。
- `BUILD_YEARS`、`COOLDOWN`、`EXPIRE_PENALTY`、`DISRUPT_RADIUS`、
  `FAR_CAP[3]`（n=4）均无实证支撑，源码已标为超参数，须做敏感性分析。
- 通道 3 的 `ALLOWED` 只有 `[3]`，即现状即类别 3 的通道 3 单元只能原类重建。
  这是数据事实而非缺陷，但会使这些单元的空间目标增量恒为 0。
