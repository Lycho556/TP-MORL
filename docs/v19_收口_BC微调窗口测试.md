# v19 收口：BC → PPO 训练长度曲线（本地，唯一重点）

按指南只做一件事：找 BC → PPO 的短期微调窗口。冻结清单（机会场、Act/Wait、
WAIT 动作、PBRS、γ、GAE λ、熵、K 大规模扫描、动作空间重设计、新奖励、
新合成机制）全部未动；BC 的 STOP 监督样本 target=0 保持固定。

**结论：不存在微调窗口 —— 指南第八节的"情况 B"。**

---

## 一、曲线（2 种子，一次训到 400 迭代、沿途在检查点求值）

一次训练沿途求值与"每个检查点各训一次"是同一条轨迹（同种子、同数据流），
但只付一次训练成本。第 0 点在加载 BC 权重**之后**求值，故它就是 BC 本身。

| 迭代数 | 相对 oracle | 标准差 | 挑错单元 | 放错年份 | 停用名额 | 与 BC 秩相关 | 环境奖励 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| **0（BC）** | **0.841** | 0.032 | 278 | 814 | 0.000 | 1.000 | 5.29e7 |
| 2 | 0.795 | 0.005 | 343 | 1071 | 0.000 | **0.557** | 4.68e7 |
| 10 | 0.774 | 0.017 | 578 | 980 | 0.000 | 0.486 | 5.08e7 |
| 50 | 0.780 | 0.025 | 536 | 975 | 0.000 | 0.427 | 4.90e7 |
| 150 | 0.778 | 0.037 | 534 | 996 | 0.027 | 0.460 | 5.01e7 |
| 400 | 0.697 | 0.154 | 1188 | 897 | 0.207 | 0.488 | 4.73e7 |

逐种子：seed 0 从 0.863 掉到 0.763；seed 1 从 0.819 掉到 0.798。**2/2 种子下降。**

三条读数：

1. **第 2 次迭代就已经掉到 BC 之下**（0.795 对 0.841），此后没有任何检查点
   回到 BC 的水平。按指南第十二节的判据（"50 迭代是否稳定 ≥ BC"），
   答案是否 —— 不必再跑第三个种子。
2. **PPO 立刻改写候选排序**：与 BC 打分的秩相关在 2 次迭代内从 1.000 掉到
   0.557，10 次迭代后 0.486。而性能同时下降，故解释很直接 ——
   **PPO 正在破坏 BC 学到的时空 ranking**（指南第十节预判的那种情形）。
3. **停用名额只在 150/400 才抬头**（0.027 / 0.207），所以 STOP 与候选的
   相对尺度失衡是**晚期症状而非主因**；主要损伤自始至终在排序上。
   这也再次说明 STOP 监督（target=0）必须保留：去掉它时前一轮实测
   立项数只有 40 而非 75、成绩 0.147。
4. **环境奖励与 oracle 计价同向**（BC 的 5.29e7 最高，其后一路偏低），
   确认这次不是口径打架 —— 上一轮小世界那种错误没有重现。

## 二、光明区最终小表

717 单元 / 25 年 / 每年 3 名额 / 只押 Floor / 年度初筛 K=20 / 每单元固定一个
目标功能 / 预算不咬。oracle = 6876（名额约束下的精确指派）。

| 方法 | n | 相对 oracle | 标准差 | 挑错单元（Where） | 放错年份（When） |

| ① 随机 | 3 | 0.757 | 0.061 | 459 | 1210 |
| ② 静态 / 近视贪心 | 3 | 0.775 | — | 342 | 1208 |

| ⑤ BC→PPO 400 迭代 | 3 | 0.474 | 0.401 | 3014 | 602 |
| ⑥ 时间感知贪心 | 3 | 0.894 | — | 124 | 608 |
| ⑦ oracle | — | 1.000 | — | 0 | 0 |

**③ 相对 ② 在 Where 与 When 上同时改善**（挑错 254 < 342，放错年份 805 < 1208），
3/3 种子超过静态基线。这就是 Gate B。

## 三、三道门槛的状态

| 门槛 | 内容 | 状态 |
|---|---|---|
| Gate A | 合成实验 TP-MORL > 纯空间排序 | **通过**（每个 α 都通过，且 ≈ oracle） |
| Gate B | 光明区 BC > 静态基线 | **通过**（0.846 对 0.775，3/3 种子） |
| Gate C | 找到稳定的 PPO 微调窗口 | **不存在** —— 按指南第八节改用 BC 作主模型 |

## 四、据此固定下来的模型与写法

**TP-MORL 的学习组件 = 监督时空打分器（BC）**，RL 微调作为**负面结果**报告。
论文措辞按指南：

> RL fine-tuning did not consistently improve the supervised initialization.

**不要**写 "PPO improves performance"。

方法叙述保持不变：城市状态 → 候选更新单元 → 时空特征 → 时空打分器 →
今年更新哪些单元 → 下一年城市状态。教师是"按已公布的规划与设施计划前瞻"的
期望折现交付价值，这是一个**需要在论文里声明的信息档**（法定图则与设施计划
已公布），不是未来真值泄漏。

## 五、服务器该跑什么（本地已收口）

只跑五行 × 3~5 种子，不跑任何开发实验（不跑 2/10/25/50/100/150/200/400 的扫描）：

    ① 随机
    ② 静态 / 近视贪心
    ③ 时间感知贪心
    ④ BC（监督时空打分器）
    ⑤ oracle
    （可选：BC→PPO 400 迭代，作为负面对照，1~2 种子即可）

    # ④ BC
    python scripts/exp_temporal_gate.py --out results_srv_bc_s$SEED \
      --unit-only --objective floor --prescreen 20 \
      --bc-init forecast --bc-only --seeds $SEED
