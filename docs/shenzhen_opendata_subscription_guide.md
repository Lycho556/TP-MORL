# 深圳市政府数据开放平台 — 订阅清单与操作说明

**证据说明**：平台目录页对非浏览器访问返回 403，搜索引擎仅索引到其服务条款页，因此**本清单中的"数据集名称"均为检索关键词而非已核实的平台条目名**。已核实的只有平台机制层面的信息（见下）。你在平台内检索后，请把实际条目名与编号回填到清单的对应行。

## 已核实的平台机制

- 主办单位：深圳市政务服务和数据管理局；运维单位：深圳市大数据资源管理中心。
- 提供**数据下载**与**数据接口**两类服务；数据资源为结构化类型，支持 xml、rdf、json、csv、xlsx 五种格式下载。
- 注册用户免费获取，享非排他使用权，**不得有偿或无偿转让**。
- **可提出"依申请开放数据资源"的申请**——目录中没有的数据走这条通道。
- 成果须注明数据来源为"深圳市政府数据开放平台"。
- 数据集详情页 URL 形如 `/data/dataSet/toDataDetails/29200_XXXXXXXX`，接口详情页形如 `/data/api/toApiDetails/29200_XXXXXXXX`。同一前缀 `29200` 在多个条目中重复出现，回填时把完整编号记下来，便于后续用接口批量调取。

## 订阅优先顺序（决定项目成败的三个字段）

整份清单 21 项里，真正卡住项目的只有三个字段。**先确认这三个，其余可以边做边补**：

1. **建筑物数据里是否有"建成年份"** → 决定层面1（地块状态生命周期）能否成立。没有它，"建筑年龄→更新压力"这条状态特征就要改用遥感影像变化检测反推，工作量翻倍。
2. **是否存在城市更新单元的空间边界矢量** → 决定层面2的动作掩码能否落到地块上。平台大概率没有，需走依申请开放，或从各区"城市更新一张图"逐个导出。
3. **分街道人口是否逐年可得（而非仅普查年）** → 决定需求侧非平稳性能否建模。只有普查年（2010/2020）的话，中间年份需插值，多期奖励的可信度会被评审质疑。

建议你先在平台里只查这三项，有结论了我们再决定是否调整层面1的实现路径。

## 检索操作建议

- 平台通常支持按**主管部门**和**主题分类**筛选。清单里给出了每项的"可能主管部门"，用它做二次筛选比纯关键词准。
- 城市更新相关数据的主管部门是**市住房和建设局**（市级统筹）与**各区城市更新和土地整备局**（区级实施）；土地与地块数据在**市规划和自然资源局**。先按这三个部门把目录整体过一遍，比逐词搜更高效。
- 遇到只提供接口不提供下载的条目，把接口详情页的**请求参数表和调用示例**截图给我，我来写调用脚本。**申请到的 appKey 请单独发给我，不要写进任何文件**，它不会进入任何产出物。

## 平台之外必须补的两类数据

清单中"替代来源"列已逐项标注，其中两类**基本确定平台不会有**，需另行获取：

- **更新单元计划公告及其附件表**（计划批次、有效期、延期、失效）——只能从各区政府门户逐份下载。这是层面2的核心数据，已有解析脚本 `renewal_unit_ingest.py` 等着接收文件。
- **地铁各期线路通车时间表**——公开可查，作为外生时序事件序列手工整理即可，条目不多。
