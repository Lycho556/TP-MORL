# UIS 区级化 — 数据需求清单（洽谈用）

> 提交对象：深圳市空间地理信息中心 / 规划和自然资源数据管理中心
> 研究范围：光明区，100 m 决策格网（171 × 161），规划期 2025–2039
> 编制依据：`docs/UIS区级化_指标体系_v1.md` §1 筛查结果
> 日期：2026-09-11

---

## 怎么用这份清单

分三档，**建议按档谈，不要一次性全要**：

- **A 档（8 项）**：没有它们，韧性和宜居两维一个指标都算不出来。**必须争取。**
- **B 档（6 项）**：有了能显著提升口径质量，没有可以用代理指标先跑。
- **C 档（4 项）**：锦上添花，或涉及口径保密，可以放到第二阶段。

每一项都写了**替代方案**——如果局里给不了，我用什么顶上、代价是什么。
谈的时候可以直接说"给不了 A3 的话我用 XX 代理，但结论只能说是代理"。

**统一要求**：坐标系 EPSG:2383（深圳独立坐标系）或 CGCS2000/EPSG:4547，
矢量给 GeoJSON / Shapefile / GDB，栅格给 GeoTIFF，表格给 CSV/Excel 并带字段说明。
时间上最好是 **2020 与 2024 两期**（我需要变化量来校准更新的效应），只有一期也能用。

## A 档｜必需（8 项）

### A1 公共服务设施 POI（分类分级）

| 项 | 内容 |
|---|---|
| **支撑指标** | 基础服务可达性 `Liv_Basic`、提升服务可达性 `Liv_Adv`、第三空间活力 `Liv_Third`、文化设施 `Hum_Culture` |
| **需要字段** | 名称、坐标、**分类编码**、等级（如医院的三甲/二甲/社康）、规模（床位数/班数/建筑面积）、建成年份 |
| **需要类别** | 小学·初中·高中、医院·社康中心、菜市场·超市、公园绿地出入口、文化馆·图书馆·博物馆、体育场馆、养老设施、咖啡·书店·健身（第三空间） |
| **格式** | 点矢量，2020 与 2024 两期 |
| **替代方案** | 高德/百度 POI 开放数据。**代价**：等级与规模字段缺失，只能算"有没有"不能算"够不够"，且商业 POI 与规划设施口径不一致 |

### A2 绿地与水体现状图层

| 项 | 内容 |
|---|---|
| **支撑指标** | 建成区蓝绿空间比例 `Aes_GreenBlue`、绿地连通度 `Aes_Connect`、开放空间品质 `Liv_Open` |
| **需要字段** | 绿地类型（公园/防护/附属/生产）、面积、是否对公众开放、水体类型（河/湖/水库/坑塘） |
| **格式** | 面矢量，优于 1:2000 精度 |
| **替代方案** | 现有 100 m 栅格的 G 类（绿地）与 water 图层。**代价**：分不清公园绿地与附属绿地，"对公众开放"这个关键属性完全缺失，开放空间品质会严重失真 |

### A3 应急避难场所与消防救援设施

| 项 | 内容 |
|---|---|
| **支撑指标** | 应急避难服务水平 `Res_Shelter`、应急救援服务水平 `Res_Rescue` |
| **需要字段** | 避难场所：位置、类型（紧急/固定/中心）、有效避难面积、可容纳人数；消防站：位置、类型（一级/二级/小型）、辖区范围 |
| **格式** | 点或面矢量 + 属性表 |
| **替代方案** | 无有效替代。**这两个指标没有数据就必须从 UIS-D 里删掉**，韧性维会从 6 个目标掉到 4 个 |

### A4 建筑普查数据（年代、结构、层数）

| 项 | 内容 |
|---|---|
| **支撑指标** | 建筑设防水平 `Res_Fortify`（韧性维权重最高的一项）、城市低碳水平 `Aes_Carbon`、更新迫切度校准 |
| **需要字段** | 建筑轮廓、**建成年份**、结构类型（砖混/框架/剪力墙/钢结构）、层数、建筑面积、用途 |
| **格式** | 面矢量（建筑基底），全区覆盖 |
| **为什么关键** | 拆旧建新的韧性收益**完全由"旧"有多旧决定**。没有建成年代，"更新提升设防"这个本项目最有说服力的论点就只能定性说，不能定量算 |
| **替代方案** | 用现有更新单元表的"现状建筑年代"字段（仅 717 个单元有，且覆盖不全）。**代价**：非更新单元的基准无法建立，算不出全区设防水平的提升幅度 |

### A5 内涝与地质灾害风险区划

| 项 | 内容 |
|---|---|
| **支撑指标** | 灾害风险综合治理 `Res_RiskExit`、海绵城市 `Res_Sponge` 的基准 |
| **需要字段** | 风险等级分区（高/中/低）、致灾类型（内涝/滑坡/崩塌/地面沉降）、重现期标准（如 50 年一遇淹没范围） |
| **格式** | 面矢量或栅格 |
| **替代方案** | 用 DEM 洼地分析 + 坡度做粗代理。**代价**：只反映地形，不含管网排水能力，会系统性高估低洼地的风险 |

### A6 不透水面 / 下垫面分类

| 项 | 内容 |
|---|---|
| **支撑指标** | 海绵城市建设水平 `Res_Sponge` |
| **需要字段** | 不透水面比例（栅格）或下垫面分类（建筑/道路/硬地/绿地/水体/裸土） |
| **格式** | 栅格，10 m 或更细；或面矢量 |
| **替代方案** | 由用地类别按经验系数换算。**代价**：同一用地类别内部差异（旧厂区几乎全硬化 vs 新园区有雨水花园）完全抹平，而这正是更新要改变的东西 |

### A7 轨道交通与公交站点、道路中心线

| 项 | 内容 |
|---|---|
| **支撑指标** | 通勤便捷度 `Liv_Commute`（升级现有 `E2r`）、所有可达性指标的路网基础 |
| **需要字段** | 轨道站点位置与出入口、线路、开通/规划年份；公交站点与线路；道路中心线含等级 |
| **格式** | 点 + 线矢量 |
| **为什么关键** | 现有所有"可达性"都是**欧氏直线距离**。光明区有大量山体与水系阻隔，直线距离会严重高估可达性。有路网才能算真实步行/骑行可达 |
| **替代方案** | OSM 路网。**代价**：深圳城中村内部支路缺失严重，恰恰是更新对象的可达性算不准 |

### A8 人口空间化数据

| 项 | 内容 |
|---|---|
| **支撑指标** | **所有"覆盖人口比"型指标的分母**（A1/A3/A5 全部依赖它） |
| **需要字段** | 100 m 或社区尺度的常住人口、年龄结构（至少老幼比）、户籍/非户籍 |
| **格式** | 栅格或社区面矢量 |
| **替代方案** | WorldPop / 腾讯位置大数据。**代价**：城中村人口密度系统性低估，而城中村是更新主战场 |

## B 档｜显著提升口径质量（6 项）

### B1 保障性住房台账
支撑 `Liv_Housing`。需要：已建/在建/规划保障房的位置、套数、类型（公租/安居/人才房）、配建来源（是否更新配建）。
**替代**：用更新单元规划的配建比例条款反推，误差大。

### B2 市政管网（给排水、电力）负荷
支撑 `Res_Infra` 市政基础设施冗余度、`Aes_Sewage` 污水处理。需要：管线走向、管径、设计与现状负荷率。
**替代**：无。没有则 `Res_Infra` 删除，韧性维再减 1 项。

### B3 街景影像或已算好的街景感知指标
支撑 `Aes_Street` 街道空间视觉感知。最好是局里已有的绿视率/界面连续度成果。
**替代**：百度街景 API 自采 + 语义分割自算，工作量约 2 周，且覆盖受街景拍摄年份限制。

### B4 历史文化遗存名录（空间化）
支撑 `Hum_Heritage` 约束。需要：文保单位、历史建筑、历史风貌区、古树名木的**空间范围**（不只是名录）。
**替代**：公开名录 + 地址地理编码，范围只能用点缓冲近似。

### B5 用地现状与规划（法定图则、单元规划）矢量
支撑：动作空间的合法性约束，比现有 `action_mask` 精确得多。需要：法定图则用地性质、容积率上限、已批单元规划范围与指标。
**替代**：现有的 269 条已批单元规划表 + 100 m 栅格类别，已在用，但精度受限。

### B6 更新单元全流程时间节点台账
支撑：本项目的**制度时滞模型**（现在的中位 3 年时滞是从 269 条样本估的）。需要：计划公告、专项规划批准、实施主体确认、用地出让、开工、竣工的日期。
**替代**：现有样本。**代价**：样本量小，时滞分布的尾部估不准，而尾部恰恰决定"交付悬崖"的位置。

## C 档｜第二阶段（4 项）

### C1 UIS 指标的官方计算口径与权重
每项指标的**精确公式、数据源、归一化方法、权重、基准值**。这是 L2 层的前提，
没有它 UIS-D 的分数无法与市级 UIS 对话。

### C2 UIS 历年分项得分（深圳市级，2020– ）
用于校准区级版：区级各维趋势应与市级趋势方向一致。

### C3 其他区的同口径数据
用于横向验证 UIS-D 的区分度。至少要 2–3 个对照区（建议宝安、龙华、坪山）。

### C4 产业与企业空间数据
支撑 `Inn_Space` 创新载体供给。需要：产业园区与孵化器边界、企业注册地与规模。
**替代**：企查查等商业数据，口径与统计局不一致。

## 谈判时建议先问的三句话

1. **"这 8 项 A 档数据，哪些是可以直接给的，哪些需要走流程、走多久？"**
   —— 先摸清边界，再决定研究设计。
2. **"UIS 的归一化口径和权重属于什么密级？能不能给方法不给基准值？"**
   —— 只要方法就能做区级内部可比，基准值是锦上添花。
3. **"如果我们做出区级版，局里希望它服务于什么场景？"**
   —— 是年度更新计划排序、还是片区统筹评估、还是对区考核？
   **这决定了指数是要"可比"还是要"可导航"，两者的设计完全不同。**
