# UIS 区级空间优化指数（UIS-D）改造方案 v1

> 面向：深圳市空间地理信息中心 / 规划和自然资源数据管理中心合作洽谈
> 对象：深圳城市指数 UIS「1 + 6 + 20 + 50 + X」→ 区级（光明区）城市更新时序－空间优化指数
> 日期：2026-09-11

---

## §0 先说清楚这份改造在做什么、不做什么

UIS 是**城市级**的综合发展评价，服务于"定方位、找方向、施方略"，横向比的是深圳与伦敦、东京、新加坡。<cite index="7-1">UIS 以"创新、宜居、美丽、韧性、文明、智慧"六大维度为支柱，构建"6+20+50+X"的综合评价体系，强调动态迭代与本地适配。</cite>

我要做的不是把 UIS 缩小一号搬到光明区，而是回答一个不同的问题：

> **一个区在未来 15 年，把有限的更新资金和名额投到哪些地块、在哪些年份投，
> 能让这个区在 UIS 的六个维度上走得最远？**

这两件事的差别决定了改造的方法。UIS 是**评价**（事后打分、横向比较），
我需要的是**优化目标**（事前决策、可被策略改变）。一个指标能不能进 UIS，
看的是它是否反映城市发展质量；能不能进 UIS-D，还要多过三道闸：

| 闸 | 名称 | 判据 |
|---|---|---|
| **G1** | 空间可归属 | 能落到 100 m 格网或某个具体更新单元上，而不是只有全区一个数 |
| **G2** | 更新可响应 | 一个更新项目建成后，这个指标会变；且在 15 年规划期内能看出变化 |
| **G3** | 区级可得 | 区一级有这个数据，或能从市级数据切出来 |

**只过 G3 不过 G1/G2 的指标不是没用**——它们是区的**背景条件**，
决定了这个区的起点，但不是这套模型的决策变量。它们进指数的"基准分"，不进目标函数。

<cite index="2-1">UIS 官方强调该体系"强调动态迭代，以适应城市发展的不同阶段"</cite>，
"本地适配"本身就是 UIS 的设计原则之一，这为区级改造提供了方法论上的正当性。

## §1 50 项指标的可优化性筛查（核心工作）

对 50 个三级指标逐条过闸，结果如下。**⭕ = 进 UIS-D 目标函数（21 项），△ = 转为约束（1 项），— = 背景条件（28 项）。**

### 1.1 创新 INNOVATION（10 项 → 可优化 1 项）

| 指标 | G1 空间 | G2 响应 | G3 可得 | 判定 | 理由 |
|---|---|---|---|---|---|
| 高水平论文产出水平 | ✗ | ✗ | ✓ | — | 机构产出，与地块用途无因果链 |
| 专利产出水平 | ✗ | ✗ | ✓ | — | 同上 |
| 研发投入强度 | ✗ | ✗ | ✓ | — | 企业行为，非空间决策结果 |
| 营商环境成熟度 | ✗ | ✗ | ✓ | — | 制度性 |
| 外来人口吸引力 | △ | △ | ✓ | — | 经住房供给间接影响，已由宜居维承接，避免重复计分 |
| **初创企业孵化水平** | ✓ | ✓ | ✓ | **⭕** | 孵化器 / 众创空间是可落点的物业类型，更新可新增 |
| 城市创新活力 | — | — | — | — | 合成指标，不独立入模 |
| 全员劳动生产率 TFP | ✗ | ✗ | ✓ | — | 现有 `Gdp` 目标是它的**粗空间代理**，见 §3 |
| 技术交易活跃度 | ✗ | ✗ | ✓ | — | |
| 跨境资本流动活跃度 | ✗ | ✗ | ✓ | — | |

> **这是一条必须对局里讲明的结论：创新维在区级更新时序决策中几乎不可优化。**
> 十项里只有"创新载体供给"能被更新项目直接改变。如果指数设计成六维等权，
> 创新维会变成一个几乎不随方案变化的常数偏置，看起来在参与评价、实际不参与决策。

### 1.2 宜居 LIVABILITY（10 项 → 可优化 6 项）

| 指标 | 判定 | UIS-D 目标名 | 说明 |
|---|---|---|---|
| **住房保障水平** | ⭕ | `Liv_Housing` | 更新配建保障性住房建面 / 新增总建面 |
| **基础服务可达性** | ⭕ | `Liv_Basic` | 小学、社区健康服务中心、菜市场 15 分钟步行覆盖人口比 |
| **提升服务可达性** | ⭕ | `Liv_Adv` | 三甲医院、高中、区级文体设施 30 分钟覆盖人口比 |
| **通勤便捷度** | ⭕ | `Liv_Commute` | **现有 `E2r`（职住偏离）即此指标的雏形**，需加轨道站点可达性 |
| **第三空间活力** | ⭕ | `Liv_Third` | 咖啡 / 书店 / 社区中心 / 健身 POI 密度（500 m 池化） |
| **开放空间品质** | ⭕ | `Liv_Open` | 公园绿地 500 m 覆盖人口比 × 人均公园面积 |
| 健康长寿水平 | — | | 期望寿命，15 年内不可归因于单个更新项目 |
| 人口结构活力 | — | | 背景 |
| 人才素质水平 | — | | 背景 |
| 居民富裕程度 | — | | 背景 |

> 宜居是**六维中最适合区级空间优化的一维**：六个可优化目标，且全部与更新的配建要求直接挂钩，
> 有现成的政策抓手（《深圳市城市更新单元规划编制技术规定》的配建比例条款）。

### 1.3 美丽 AESTHETICS（9 项 → 可优化 6 项）

| 指标 | 判定 | UIS-D 目标名 | 说明 |
|---|---|---|---|
| **生态空间保护水平** | ⭕ | `Aes_Eco` | **现有 `Eco` 目标直接对应** |
| **建成区蓝绿空间比例** | ⭕ | `Aes_GreenBlue` | 更新后绿地水域面积 / 建成区面积 |

| 全年空气质量 PM2.5 | — | | 区内空间差异远小于测量误差 |

| 城市目的地吸引力 | — | | 同上 |
| **街道空间视觉感知** | ⭕ | `Aes_Street` | 街景绿视率 + 界面连续度 + 天空开阔度，可由街景图像算 |

### 1.4 韧性 RESILIENCE（8 项 → 可优化 6 项）

| 指标 | 判定 | UIS-D 目标名 | 说明 |
|---|---|---|---|
| 市政基础设施冗余度 | ⭕ | `Res_Infra` | 需给排水 / 电力管网负荷数据 |
| **应急避难服务水平** | ⭕ | `Res_Shelter` | 应急避难场所服务半径覆盖人口比 |
| 自然岸线保有率 | — | | **光明区无海岸线，此指标在本区不适用**；建议区级版替换为"河道生态岸线率" |
| 韧性城市顶层设计 | — | | 制度性，全区一个数 |
| **建筑设防水平** | ⭕ | `Res_Fortify` | **拆旧建新本身就是提设防**：按建成年代 × 结构类型赋设防等级，算加权提升量 |
| **应急救援服务水平** | ⭕ | `Res_Rescue` | 消防站 5 分钟、急救 10 分钟到达覆盖人口比 |
| **海绵城市建设水平** | ⭕ | `Res_Sponge` | 可渗透面积占比，更新可直接改变 |
| 灾害风险综合治理 | ⭕ | `Res_RiskExit` | **内涝 / 地质灾害高风险区内的居住人口减量**——更新把人从风险区搬出来 |

> **韧性是被低估的一维。** 城市更新的本质是拆旧建新，而"旧"恰恰意味着
> 设防等级低、硬化率高、管网老化、常在风险区。**韧性维是更新最直接的收益方向**，
> 但现有模型里一个韧性目标都没有——这是当前目标体系最大的缺口。

### 1.5 文明 HUMANISM（7 项 → 可优化 1 项 + 约束 1 项）

| 指标 | 判定 | UIS-D 目标名 | 说明 |
|---|---|---|---|
| 市民文明素养水平 | — | | 非空间 |
| **文化资源丰富度** | **△ 约束** | `Hum_Heritage` | 文保单位 / 历史建筑 / 古树名木。**更新不得减少，写成硬约束而非目标** |
| 多元文化包容性 | — | | |
| **文化空间与设施共享** | ⭕ | `Hum_Culture` | 更新配建文化设施建面 |
| 全球文化影响力 | — | | 城市级 |
| 公共文化参与与消费 | — | | |
| 市民公益参与度 | — | | |

> 文明维在更新问题里**主要以底线约束形式出现，而不是最大化项**。
> 这符合规划实务：历史文化保护是"不得触碰"，不是"越多越好"。
> 把它写成目标会产生错误激励（策略为了拿分去"制造"文化设施）。

## §2 筛查结果：这本身就是一个可发表的发现

| 维度 | UIS 指标数 | 进 UIS-D 目标 | 约束 | 可优化率 |
|---|---|---|---|---|
| 创新 INNOVATION | 10 | 1 | 0 | **10.0%** |
| 宜居 LIVABILITY | 10 | 6 | 0 | **60.0%** |
| 美丽 AESTHETICS | 9 | 6 | 0 | **66.7%** |
| 韧性 RESILIENCE | 8 | 6 | 0 | **75.0%** |
| 文明 HUMANISM | 7 | 1 | 1 | **14.3%** |
| 智慧 INTELLIGENCE | 6 | 1 | 0 | **16.7%** |
| **合计** | **50** | **21** | **1** | **42.0%** |

（本表由 `python3 -m tpmorl.objectives.uis` 直接算出，与代码登记表同源，不手工维护。
其中 21 项可优化指标里，现有目标已粗口径覆盖 **1** 项（生态空间保护水平），
其余 **20** 项需要局里的空间数据。）

**结论：UIS 的 50 项指标中，只有 42% 具有区级空间可优化性，且高度集中在宜居、美丽、韧性三维。**

这条结论有三个用处：

1. **对局里**：说明区级版不能照搬六维等权，否则三分之二的权重压在几乎不动的维度上，
   指数会对方案差异不敏感——**"不敏感的指数没有导航价值"**，这正是 UIS 自己反对的静态榜单。
2. **对论文**：这是一个方法论贡献——**综合城市评价指数向空间优化目标函数转化的可操作筛查准则（G1/G2/G3）**，
   不只适用于 UIS，也适用于其他城市指数。
3. **对模型**：明确了目标函数应该长什么样——**以宜居 + 美丽 + 韧性为主体的三维权衡**，
   创新 / 文明 / 智慧作为背景分与约束。

### 建议的区级权重结构

不建议六维等权。建议**分层**：

```
UIS-D 总分 = w_opt · 可优化部分 + w_base · 背景部分     (受文明维约束)

可优化部分 = 宜居(1/3) + 美丽(1/3) + 韧性(1/3)         ← 决策变量
背景部分   = 创新 + 文明 + 智慧的区级基准分            ← 不随方案变化
```

`w_opt : w_base` 的取值需要与局里商定——这是**政策判断，不是技术判断**，
我在 §5 把它列为要问的问题。

## §3 与现有 11 个优化目标的对照

现有目标（`src/tpmorl/objectives/reward.py`）：

| 现有目标 | 含义 | 映射到 UIS 维度 | 对应 UIS 指标 | 口径差距 |
|---|---|---|---|---|
| `Gdp` | 产业产出效用 | 创新 | TFP（粗代理） | **大**：按用地类别赋常数，不含企业实际产出 |
| `Eco` | 生态本底效用 | 美丽 | 生态空间保护水平 | **小**：口径接近，可直接对齐 |
| `Res` | 居住承载 | 宜居 | 住房保障水平（部分） | **中**：只有总量，无保障房结构 |
| `Emp` | 就业承载 | 创新 / 宜居 | 就业密度 | 中 |
| `Aec` | 环境舒适度（宜居/居住比） | 宜居 | 开放空间品质（粗代理） | **大**：无真实绿地与 POI |
| `E2r` | 职住偏离 | 宜居 | **通勤便捷度** | **小**：概念直接对应，缺轨道可达性 |
| `Cpt` | 用地紧凑 / 兼容度 | 美丽 | 空间共鸣（部分） | 中 |
| `Floor` | 交付建面 | — | 非 UIS 指标（实施产出量） | 保留为实施类目标 |
| `Cost` | 资金成本 | — | 非 UIS 指标（投入量） | 保留 |
| `Disrupt` | 施工扰动 | 宜居（负） | 生活品质的施工期损失 | 保留，UIS 无对应项但实务必须计 |
| `Expire` | 计划失效 | — | 制度类 | 保留 |

**关键判断：现有 7 个空间目标全部是"用地类别 → 常数效用 × 格数"的粗口径。**
这意味着模型分不清同一类别里的两块地。任何真正的 UIS 指标都需要**真实空间图层**
（POI、绿地、避难场所、管网、建筑年代、风险区），这就是要向局里要数据的根本原因。

**现有 11 个目标覆盖了 UIS-D 20 个目标中的 6 个，而且都是粗口径。缺口是：**

- **韧性维 6 个全缺**（当前模型完全没有韧性目标）
- 宜居维缺 4 个（住房保障结构、基础服务、提升服务、第三空间）
- 美丽维缺 4 个（蓝绿比、碳、街景、连通度）

## §4 三层落地路线

### L0 — 现在就能做（不需要局里任何新数据）

把现有 7 个空间目标按 §3 归到 UIS 六维，做维度内归一化聚合，得到**UIS-D 简版**。
六维中创新、宜居、美丽三维有值，韧性、文明、智慧三维为空。

**价值**：立刻能产出"按 UIS 框架表达的权衡前沿"，可以拿去和局里谈；
且能定量说明缺口有多大（三维为空）。
**已实现**：`src/tpmorl/objectives/uis.py`，见 §6。

### L1 — 需要局里的基础空间数据（下周洽谈的主要目标）

补齐宜居、美丽、韧性三维，目标数从 6 个增加到 21 个。
所需数据见独立清单 `docs/UIS区级化_数据需求清单.md`。
这些基本都是规自局与空间地理信息中心的常规存量数据，获取难度不高。

### L2 — 需要 UIS 官方口径（第二阶段）

要到 UIS 的**归一化方法、权重、基准值与样本城市数据**，
使 UIS-D 的分数与市级 UIS 可比，从而能说"光明区在本市/全球样本中的位置"。
这一层依赖合作深度，不是数据申请能解决的。

## §5 需要与局里确认的判断性问题（非数据问题）

这五条是**政策判断**，我给不出答案，必须问：

1. **区级版要不要保留六维等权？** 我的测算是创新/文明/智慧三维可优化率只有 10–17%，
   等权会让指数对方案不敏感。局里能接受分层加权吗？
2. **背景分与可优化分的比例（`w_opt : w_base`）怎么定？**
3. **"自然岸线保有率"在无海岸线的区怎么处理？** 置零、剔除后重新归一、还是替换为河道生态岸线率？
   这关系到区与区之间能不能横向比。
4. **文化资源丰富度写成约束（不得减少）还是目标（越多越好）？** 我倾向约束，需要确认。
5. **UIS 的归一化是极差标准化、Z 分数还是对标基准值？** 这决定 UIS-D 能不能与市级分数对话。

## §6 代码侧的对应改造

已新增 `src/tpmorl/objectives/uis.py`：

- `IND_REGISTRY`：50 项指标的完整登记表，每项标注 `dim / gate / status(L0|L1|L2) / formula / data_req`，
  **筛查结论以可执行的数据结构落库，不是只写在文档里**——后续加数据只改登记表，不改模型。
- `DIM_OF_LEGACY`：现有 11 目标 → UIS 六维的映射（§3 的表）。
- `uis_d(rvec, scale)`：按六维聚合，返回每维分数与总分；缺数据的维度返回 `NaN` 而不是 0，
  **防止"没数据"被当成"得分为零"**。
- `coverage()`：打印当前各维的指标覆盖情况，用于向局里展示缺口。

**目标函数本身暂不改动。** 理由：L1 数据未到位，现在改会把 20 个目标里的 14 个写成空壳，
既跑不出结果，又会让已有的 v11 结论无法与新版对齐。正确的顺序是
**先拿数据、再扩目标、再重跑**。当前这一层是聚合与登记，与现有训练完全兼容。
