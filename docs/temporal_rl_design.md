# 结合 pSO 骨架 + 深圳开放数据的时序强化学习方案

**结论先行：可以做，而且 pSO 提供的东西比预想的更关键——它解决了坐标系这个卡点，并且它的目标函数是可微的，这直接给了我们一个别人没有的时序奖励设计。但方案必须绕开一个硬约束：平台上没有更新单元的空间几何。下面给出绕法。**

---

## 一、pSO 仓库实测：它到底给了什么

仓库是 Luo & Huang (2023) *IJGIS* 论文的配套代码，DOI 10.1080/13658816.2023.2178001。方法是**概率化连续松弛 + 梯度下降的一次性多目标用地优化（pMOLU/GDA）**，不是强化学习，也没有时间维——与我们此前核查的 MOGNNAC 属于同一类"一次性布局"工作。学长的场景包是把它改装成 RL 形状的产物。

三个实测发现，按重要性排：

**1. 坐标系找到了。** `Ws/road.tif`、`water.tif`、`slope.tif` 带完整投影：

- PCS：`Xian_1980_3_Degree_GK_CM_114E`（西安80 三度带高斯-克吕格，中央经线 114°E，东偏 500000 m）
- 左上角控制点 (484462.193, 2526377.007)，像元 5 m × 5 m，尺寸 3217 × 3401 — **与 `LU.tif` 完全一致**
- 换算到 WGS84：经度 113.8486–114.0053，纬度 22.6824–22.8359 — 正是光明区

`LU.tif` 自身控制点为 0、无 GeoKey，但既然与 `road.tif` 像元对齐，**把投影和控制点直接抄过去即可完成配准**。我上一轮把"无坐标系"列为最大单点风险，这一项现在解除。

顺带说明：学长场景包里那两张"只随列变化"的合成 `suit_road`/`suit_water`，其真实版本一直躺在这个仓库里没被用上。

**2. 七个目标函数全部可微。** `objs.py` 用 TensorFlow 算子写在软概率张量 `LU (H,W,C)` 上，每个目标都同时给出张量式（`Gdp/Eco/Res/Emp/Aec/E2r/Cpt`）与数值式（`Eval`），转换成本 `Cov` 作约束项处理。构成要素：用地效用矩阵 `UUM`、边际效用递减变换 `eta(p)=1-p²/3`、`avg_pool`（r=100, s=50，即 500 m 邻域聚合）、职住偏离项、相容度矩阵 `CM`/`CCM`、以及对照原始用地的转换项。

**这是我们相对于 MOGNNAC 等 RL 竞争工作的独有资产**，理由见第三节。

**3. 类别体系比场景包细。** 原始 12 类：`R1, R2, RC, C, CBD, IH, I1, I2, A, E, G, U`，DN=0 为 Restrict、DN=15 为 Mask。学长的场景包压成了 8 类、120×160 格网。**建议回到原始 12 类重建场景**，因为更新方向（"商业+居住"、"工业升级"等）在 8 类下无法表达。

## 三、方案设计

### 3.1 破解"样本太少"的关键设计

直觉做法是把光明区的 14 个更新项目当成动作空间——这行不通，样本量太小。

**改为两阶段：全市标定、光明应用。**

- **阶段一（标定）**：用全市 742 条更新单元计划 + 271 条已批单元规划（含年度分箱），标定一个**时序可行性模型** `P(单元在第 t 期获批 | 街道属性, 拆除范围面积, 更新方向, 计划已存续年限)`。样本 1013 条，覆盖全市十个区、跨 2018–2022 五年，足以拟合一个生存分析或离散时间 logit。
- **阶段二（应用）**：把标定好的模型作用到光明区的**全部候选地块**上，产生随时间变化的可行性概率 → 转成 MDP 的动作掩码或状态特征。

这样既用上了全市数据的统计量，又保留光明区作为空间案例。**光明区的 14 个真实更新项目转而用作验证集**，检验策略推荐的时空次序是否与现实一致——这比拿它们做训练集有价值得多。

### 3.2 MDP 定义（层面 2 为核心）

设格网 `G`（建议 500 m 聚合，由 `gm_index_map` 式索引从 5 m 栅格重新粗化；12 类保留）。

**状态** `s_t = (L_t, A_t, τ_t, b_t)`
- `L_t ∈ Δ^12`：概率化用地张量，沿用 pMOLU 的软表示（**直接复用 `M.prob_LU`**）
- `A_t`：可行性得分层，来自 3.1 标定的模型
- `τ_t`：**计划有效期倒计时层**——每个已立项单元剩余有效期（深圳更新单元计划有效期制度）。未立项地块置 0
- `b_t`：本期剩余拆除量预算（标量或按街道分量）

**动作** `a_t`：在本期允许集合内，选择若干地块及其目标用地类。允许集合 = `mask_forbidden`（生态控制线/历史建筑/水体）∩ 候选地块 ∩ **时序掩码** `{i : A_t(i) ≥ θ 或 τ_t(i) > 0}`。

**转移**：
- 被选中地块用地类改变，同时 `τ` 重置为新的计划有效期
- 未被选中但 `τ_t > 0` 的地块 `τ` 减一；`τ` 归零则该单元计划失效，回到未立项状态（**这是"逾期失效"机制，是深圳制度的真实特征，也是时序模型区别于一次性优化的核心**）
- `A_{t+1}` 按标定模型更新

**奖励** —— 这是全案的技术亮点：

```
r_t = Σ_k w_k · [f_k(L_t) − f_k(L_{t−1})]  −  λ · Cov(L_t, L_{t−1})  −  μ · Disrupt_t
```

其中 `f_k` 直接取 pSO 的七个可微目标函数，`Cov` 取其转换成本项。三点说明：

1. **稠密奖励**。MOGNNAC 论文明确把"序贯形式下中间奖励难以定义"作为拒绝序贯建模的理由。因为 pSO 把全局目标写成了对整张图的可微函数，我们可以直接取**逐期增量**作为中间奖励——这个反驳是具体的、可实现的，不是修辞。
2. **全局耦合被保留**。`eta(p)=1−p²/3` 让单格价值依赖全图类别构成，正是竞争工作用来论证"必须一次性决策"的性质；增量奖励天然把它算进去了。
3. **`Disrupt_t` 是新增项**，用 pSO 的非对称 `CCM` 加多期折现构造：同一片区连续多期施工要罚，这是一次性优化在原理上表达不了的。

**基线对照**：把 T 折叠成 1、令 `τ` 恒有效，就退化为 pMOLU 的一次性优化。**同一套目标函数、同一份数据、同一个区，一次性 vs 时序，构成最干净的对照实验**——这是仓库带来的最大方法论便利。

### 3.3 数据与模块对应

| MDP 组件 | 数据来源 | 状态 |
|---|---|---|
| 底图 `L_0` | pSO `GMCase/LU.tif`（12 类，5 m） | **已有** |
| 坐标系 | 从 `Ws/road.tif` 转写 | **已有** |
| 道路/水体/坡度约束 | `Ws/*.tif`（真实、已配准） | **已有** |
| 七目标 + 转换成本 | `objs.py` + `UUM/CM/CCM.csv` | **已有** |
| 禁建掩码 | 生态控制线 + 历史建筑（10 条） | 需补生态线矢量 |
| 时序可行性 `A_t` | 市级 742 + 271（年度分箱） | **需你登录下载** |
| 有效期 `τ_t` | 计划公告文件中的有效期条款 | 需从公告正文提取 |
| 验证集 | 光明区 14 个更新项目 + 63 个整备项目 | API 可取 |
| 建筑年龄（层面 1） | 光明区无 | **缺口** |

### 3.4 空间定位——这是最大的剩余风险

1013 条更新记录只有"名称 + 街道"，没有几何。三条出路，建议并行走前两条：

- **A（推荐，可自动化）：街道级时序预算。** 不做地块级定位，而是把每期每街道的可拆除总量作为预算约束 `b_t`。光明区 6 个街道 × 8 期 = 48 个预算格，从 1013 条记录按街道-年度聚合即可得到。**这条路完全不需要几何，且已经足以让时间维产生实质约束。**
- **B（加分，半自动）：光明区 14 个项目手工定位。** 数量小，从计划公告附图定位到 500 m 格网是一两天的工作量，用作验证集的空间锚点。
- **C（可选）：名称地理编码。** 更新单元名多含"××股份公司旧厂房""××村"，可与村居/社区边界匹配。精度有限，作为 A 的补充。

**明确记录：如果 A、B 都不做，时序维度就只是一个没有内容的循环。这一步不能省。**

## 四、分阶段推进

**第 0 阶段（本周，不依赖任何新数据）**
1. 把 `road.tif` 的投影与控制点写入 `LU.tif`，产出带坐标的用地底图，与光明区行政边界叠合验证
2. 按 500 m 重新粗化，保留 12 类，生成 `L_0` 与索引映射
3. 跑通 `Opt_GMcaseGDA.py`，复现一次性优化基线，确认目标函数数值可复现

**第 1 阶段（依赖你下载市级两张表）**
4. 下载 29200/00303355 与 29200/00303518（四个年度文件全要），按街道-年度聚合
5. 拟合离散时间可行性模型，输出 `A_t` 与街道预算 `b_t`
6. 从计划公告提取有效期条款，构造 `τ` 的初始值与衰减规则

**第 2 阶段（建模）**
7. 实现环境：状态/动作/掩码/转移，奖励复用 `objs.py`（把 TF1 静态图改写为 TF2 或 PyTorch 的可微函数）
8. 训练策略（建议 PPO + 动作掩码），与一次性基线对照
9. 用光明区 14 个真实项目做时空次序验证

**第 3 阶段（层面 1，视数据而定）**
10. 若能从规自局拿到光明区建筑普查或三旧图斑的建成年份，加入 `age_t` 与容积率利用率作状态维；拿不到就用 C 类危险建筑（49 条）+ 超高层（35 条）做粗代理，并在论文中明确标注为代理变量

## 五、三个需要你决定或去拿的东西

1. **登录下载市级两张表**（29200/00303355、29200/00303518 全部四个文件）。它们不在 API 目录，我的接口取不到，只能你实名登录后下载。**这是整个层面 2 的唯一数据入口，优先级最高。**
2. **确认走 A 还是 A+B**。只走 A 的话时间维是街道级预算约束；加 B 才能做到地块级时序掩码。B 的工作量约一两天。
3. **确认坚持光明区**。光明区的优势是 pSO 已有 5 m 真实底图和标定好的目标函数；劣势是更新样本仅 14 个。若改用坪山（117 条已批计划、含批次字段、API 可取），时序数据会好得多，但底图和目标函数要重做。**我的判断是留在光明**——底图和可微目标函数的价值高于样本数，而样本数问题已由 3.1 的"全市标定、光明应用"设计化解。
