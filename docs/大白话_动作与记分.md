# 大白话：模型每年到底在做什么决定，分数又是怎么算出来的

面向完全不懂强化学习的人。所有数字 2026-09-10 由代码现算，来源：
`src/tpmorl/env/schedule.py`、`src/tpmorl/rl/env_gym.py`、`src/tpmorl/objectives/reward.py`、`data/processed/gm_dataset_v1/meta.json`。

---

## 零、先把几个术语翻译成人话

| 术语 | 人话 | 在我们这儿具体指什么 |
|---|---|---|
| **状态** state | 现在是个什么情况 | 717 个更新单元，每个此刻卡在制度流程的哪一格 |
| **动作** action | 这一步做什么决定 | 今年立哪几个更新单元的项，各自改成什么用途 |
| **一步** step | 决策的时间颗粒 | **一年**。走 15 步 = 一个规划期 |
| **回合** episode | 完整玩一遍 | 从第 1 年走到第 15 年 |
| **奖励** reward | 这一年得几分 | 11 个指标各记一个分 |
| **折扣** γ | 早拿分比晚拿分值钱 | γ=0.95，第 15 年的分只算 0.49 折 |
| **掩码** mask | 法规不允许的选项，直接划掉不给选 | 年配额、预算、只能动没立过项的单元 |
| **策略** policy | 一套"看到什么情况就怎么做"的规矩 | 训练出来的最终产物 |
| **回报** return | 15 年总成绩 | 逐年折扣后加起来 |

一句话概括：**让计算机在光明区的沙盘上反复玩 15 年的更新规划，每年做一次决定，玩完打分，
玩几百万遍，它就学出一套"什么时候动哪块地"的规矩。**

## 一、六个状态：一个更新单元的一生

每个单元在任何时刻，一定处在下面六格中的某一格：

| 代号 | 名字 | 人话 |
|---|---|---|
| **S0** | 未立项 | 这块地还没动，随时可以报 |
| **S1** | 计划有效期内 | 已经报上去了，正在等批。**有倒计时**（3 年 + 最多延 2 年） |
| **S2** | 单元规划已批 | 批下来了，还没开工 |
| **S3** | 实施中 | 正在拆、正在建。**周边会受施工影响** |
| **S4** | 已完成 | 建成了。**这一年才给交付分** |
| **S5** | 计划失效 | 有效期到了还没批下来，作废。**本规划期内不能再报** |

**走法**（这是制度规则，不是模型自由发挥）：

```
S0 ──立项──> S1 ──批准──> S2 ──次年开工──> S3 ──建5年──> S4（终点）
                │
                └──有效期耗尽仍未批──> S5（本期出局）
```

---

## 二、每个状态下有哪些选择？——**这里有个关键点，很多人会想错**

| 状态 | 模型能做什么选择 |
|---|---|
| **S0 未立项** | ✅ **可以选**：立项（并指定改成什么用途），或者今年先不动它 |
| **S1 有效期内** | ❌ **没得选**。环境自动推进，每年掷一次骰子看批不批 |
| **S2 已批待实施** | ❌ **没得选**。次年自动开工 |
| **S3 实施中** | ❌ **没得选**。建设倒计时，到点自动建成 |
| **S4 已完成** | ❌ 终点，本回合不再动 |
| **S5 失效** | ❌ 吸收态，本规划期内不再回到 S0 |

**所以整个模型里，真正的决策只有一个：今年立哪几个项、改成什么用途。**

一旦立了项，后面全是制度和运气在推着走——批不批看概率，开工时间固定，建设年限固定。
这正是我这个研究要问的问题：**既然后面都由不得你，那"什么时候按下立项这个按钮"就是唯一能优化的东西。**

（补充一句：代码里"推进"这个动作是**每年对所有 S1 单元自动执行**的，
不是模型选出来的。这是一个简化——现实中报不报草案、要不要申请延期，是有选择余地的。
这一点在论文的局限里要写。）

## 三、动作长什么样：从 1986 个选项里挑最多 3 个

**候选池**：717 个单元 × 各自允许的目标用途 = **1986 个"单元 × 用途"配对**。
每个单元平均有 **2.77** 个可选用途（中位 3，最少 1 个，最多 3 个），不是 12 个都能随便改。

**用途一共 12 类**：R1 一类居住、R2 二类居住、RC 商住混合、C 商业、CBD 中心商务、
IH 高新产业、I1 一类工业、I2 二类工业、A 公共设施、E 非建设、G 绿地、U 公用设施。

**哪些用途能选，由这块地属于哪个"更新通道"决定：**

| 通道 | 单元数 | 典型可选目标 |
|---|---|---|
| **P1 产业升级** | 217 | R2 二类居住 / C 商业 / I1 一类工业 |
| **P2 旧居住** | 122 | R1 一类居住 / R2 二类居住 / C 商业 |
| **P3 商服提升** | 83 | C 商业（只有一个选项） |
| **P5 农转用储备** | 295 | R2 二类居住 / I1 一类工业 / G 绿地 |

**每年的动作 = 从这 1986 个配对里挑出 0 到 3 个。** 可以一个都不挑（模型有个"停"的选项）。

**三道硬约束，违反的选项直接从菜单上划掉，模型根本看不见：**

1. **年度配额 3 个** —— 依据：光明区 2011–2018 年计划公告数均值 3.1、上限 6
2. **年度预算 900** —— 花超了不行；没花完可以攒，但最多攒到 3 倍（2700）就作废
3. **只能动 S0 的单元** —— 已经在流程里的、已建成的、已失效的，都不能重复报

一个单元的成本 = 格数 × (拆除补偿 50 + 用途转换成本)。中位单元 11 格，成本约 990。
**所以年预算 900 大概只够动一个中等大小的单元** —— 钱是真的紧，实测预算利用率 0.71–0.98。

## 四、分数是怎么算出来的：四步

### 第 1 步：每年算 11 个原始分

**7 个"空间分"**（借鉴既有用地评价框架，算的是**逐年变化量**，不是绝对水平）：

| 代号 | 是什么 | 方向 |
|---|---|---|
| Gdp | 经济产出 | 越大越好 |
| Eco | 生态质量 | 越大越好 |
| Res | 居住适宜 | 越大越好 |
| Emp | 就业供给 | 越大越好 |
| Aec | 宜居可达性 | 越大越好 |
| E2r | 职住失衡度 | **越小越好** |
| Cpt | 用地兼容性 | 越大越好 |

**4 个"时序分"**（这 4 个是本研究新加的，是"择时"的载体）：

| 代号 | 是什么 | 方向 | **什么时候记这笔账** |
|---|---|---|---|
| **Floor** | 交付建筑面积 | 越大越好 | **只在转入 S4（建成）那一年记**。= 通道容积率上限 × 格数 × 100 ㎡ |
| **Cost** | 资金成本 | **越小越好** | **也只在建成那一年记**。= 拆除补偿 + 用途转换成本 |
| **Disrupt** | 施工扰动 | **越小越好** | S3（施工中）**每一年都记**。半径 3 格（300 米）内的居住人口 |
| **Expire** | 计划失效 | **越小越好** | 每失效一个单元扣 1 分 |

### 第 2 步：把 11 个分各自除以一个"分母"

因为 GDP 的量纲是亿元、建面是平方米、失效是个数，不除掉没法加。
分母的取法是：先让几套参考策略跑一遍，取它们能达到的上界。

### 第 3 步：按权重加权求和 —— 这就是那个"偏好拨盘 α"

α 从 0 拨到 1，代表决策者"偏生态"还是"偏经济"。归一化后的实际权重：

| α | Gdp / Emp / Floor 各 | Eco / Aec 各 | Cost / Disrupt / Expire 各 | Res / E2r / Cpt 各 |
|---|---|---|---|---|
| **0.0 极端偏生态** | 0 | **34.5%** | 6.9% | 3.4% |
| **0.5 折中** | 14.7% | 14.7% | 5.9% | 2.9% |
| **1.0 极端偏经济** | **25.6%** | 0 | 5.1% | 2.6% |

**必须诚实说的一点**：11 个目标里**真正随 α 变动的只有 5 个**
（GDP / 就业 / 交付建面 一组，生态 / 宜居可达 一组），其余 6 项权重恒定在 2.6%–6.9%，
是背景约束项。所以对外只能说"5 目标两极权衡 + 6 项固定约束"，**不能说"11 目标权衡"**。

### 第 4 步：逐年打折加起来

第 t 年的分乘以 0.95^t 再累加。所以**同样一件事，早做比晚做值钱**——
第 1 年的分算 100%，第 15 年的分只算 48.8%。**这就是"择时"信号的全部来源。**

## 五、把时间线串起来：一次立项的完整账

假设模型在**第 t 年**立了一个项：

```
第 t 年      立项 → 进 S1。这一年：扣预算，但一分不得
第 t+τ 年    批准 → 进 S2。τ 按真实概率掷骰子：
             第1年批 17.4%、第2年 21.2%、第3年 23.9%、第4年 27.7%、第5年 17.9%
             （中位数 3 年；5 年还没批下来 → 进 S5，本期出局，扣 1 分）
第 t+τ+1 年  开工 → 进 S3。开始每年扣"施工扰动"分
             ……建 5 年，每年都扣扰动分……
第 t+τ+6 年  建成 → 进 S4。**这一年才拿到交付建面分，也才记成本账**
```

**所以：建成年 = 立项年 + τ + 6。**

按中位 τ=3 算，**第 5 年之后立项的，15 年内建不成，交付分是 0。**

---

## 六、这套算法现在最大的毛病，用这张时间线一看就明白

既然 Floor 只在建成那年给分，那么：

- 第 5 年以后立的项，在 15 年规划期内**永远拿不到交付分**
- 但它**照样扣预算**（预算是立项当年就扣的）
- 所以对模型来说，那半张时间轴是一片**"零梯度盲区"**——做什么都一样，学不到东西

实测：**36% 到 48% 的立项落在第 8 年以后**。
而预算是真的咬住的（利用率 0.71–0.98），说明这些钱是白花的。

**这说明两件事：**
1. 策略还**没收敛好**——一个学明白了的策略，不该把近一半的预算砸在必然零分的年份上。
2. 更根本的是，**"只认竣工才给分"这个记分方式本身就不像实务**。
   规划局的台账是分阶段的：计划立项 / 规划批准 / 用地出让 / 开工 / 竣工，各有各的完成率口径。
   如果改成"批准给一部分分、竣工给剩下的"，盲区就变成了有坡度的地形，模型才学得动。

**这也是我明天最想向规划局的老师确认的问题：你们统计完成率，到底算到哪个节点。**

## 附：一句话版本（如果只能说三句）

> 每年模型只做一个决定：**从 1986 个"哪块地 + 改成什么"的组合里，挑最多 3 个报上去**。
> 报上去之后就由不得它了——批不批看概率、建多久是定数，**建成年 = 立项年 + 审批时滞 + 6 年**。
> 分数按 11 个指标算、按偏好加权、按年份打折，**早做比晚做值钱**，
> 但因为只有"竣工"才给交付分，**第 5 年以后报的项目在 15 年里注定是零分**。
