# v17 改动实施记录

## 0 这一版要解决的问题

v16 的主判据成立，**次判据不成立**：

> 主组的立项年份分布与均摊无法区分——卡方 p=0.999，立项重心 6.98 对均摊基准
> 7.00（`results_v16/quicklook.txt`）。十六组里没有一组出现"前移"。
> 规则基线 frontload 的 CRH_T=0.613 反而高于策略的 0.301。

即：**到 v16 为止，强化学习没有学到时间维度上"什么时候建什么合适"。**

原因不在优化器，在环境。`docs/择时机制_诊断_v1.md` §3 与 `env_gym` 顶部的
"非平稳性"一节早已写明：候选集是平稳的，预算结转只改变"能做多少"、不改变
"何时做更好"，成本与收益都与面积线性、无规模报酬，故攒钱无回报；于是明年的
机会集不优于今年，而 γ<1 始终把动作往前推——**等待永不严格占优**。

此前唯一的非平稳通道 `FAR_GROWTH` 是**全局同步**的：所有单元同时变好，
只改变"整体早做还是晚做"，不改变"先做哪个、后做哪个"。后者才是择时问题。

## 1 门槛实验：先证明学习器有能力学会"等"（`scripts/exp_timing_gate.py`）

在把机会场接进真实环境之前，先在一个**最优解可以穷举算出**的三地块最小情景上
问：这套学习器（掩码指针 + PPO + 逐年奖励）有没有能力学会等？

情景：B 现在就好且以后不变（应第 0 年动）、A 现在一般而第 onset 年起变好
（应等到 onset）、C 一直不好（低优先，且不该为它一直等）。年度配额 1，
资金刻意不咬——把"等"的唯一理由留给机会场。

判据三条，缺一不可：
1. A 的立项年 >= onset（学会了等）；
2. B 的立项年 == 0（没有因为学会等而变成一律拖延）；
3. 折现回报 >= 穷举最优的 95%（等的位置也大致对）。

第 2 条是必须的：一个"什么都往后推"的退化策略也能满足第 1 条，那不是择时，
只是另一种均摊。

### 实测结果（十一档，每档 3–5 个种子）

**没有任何一档同时满足三条判据。** 逐档的失败方式并不相同，须分别记下：

| 档 | 做法 | 结果 |
|---|---|---|
| 基准 | 阶跃场、前瞻 0、熵 0.01、300 迭代 | A 恒在第 2 年（最优 4），回报比 0.743 |
| 奖励时点 | 收益改在**立项年**计（去掉 lead 年延迟） | 与基准逐位相同 0.743 |
| 熵 ×5 | `ent_c` 0.01 → 0.05 | 与基准逐位相同 0.743 |
| 迭代数 | 300 → 1000 | 与基准逐位相同 0.743 |
| 折现率 | γ 0.95 → 0.99 | 略差 0.706 |
| 熵 ×20 | `ent_c` → 0.2 | **训练崩掉**：3 种子里 1 个整回合不立项，均值 0.491 |
| 场形状 | 阶跃 → 逻辑斯蒂爬升（时间常数 3 年） | 立项年**更早**（第 1 年），回报比 0.947 |
| 幅度 | lo/hi 从 0.6/1.6 放大到 0.3/3.0 | 立项年**更早**（第 0 年），回报比 0.745 |
| 观测前瞻 | 加入趋势 mult(t+K) − mult(t)，K=1/3 | 立项年不变 |
| 每轮回合数 | 8 → 32，迭代 500 | **1/3 种子学会了等**（A=7，正是最优年），但该种子把 B、C 也一起推后（退化解）；组均值 0.929 |
| 势函数整形 | PBRS，爬升场 + 前瞻 3 | 唯一把回报做到最优 95% 以上的一档（3/3 种子，均值 0.967；同场形同前瞻的未整形对照 0.930），但**立项年仍未推后** |
| 势函数整形 | PBRS，阶跃场 | 不稳定，均值 0.491 |

### 两条结论

**(a) 环境改造是必要的，但不是充分的。** 把"等"变得有价值之后，这套学习器
仍然倾向于按当期价值降序尽快填满配额。原因至少有两层：

* **阶跃型机会改善隔着多步壁垒**：onset 之前"多等一年"逐年都是净亏（同样的
  收益推迟一年 = 乘 γ），只有连等到 onset 才回本。PPO 做的是局部策略改进，
  单步偏离一律被惩罚，改进路径不单调。
* **爬升型机会改善的择时收益又低于梯度噪声**：把场改成平滑爬升后每多等一年
  本身就净赚，但贪心解相对最优只差 5.3%，这个差在每轮 8 个回合的梯度估计里
  看不见——把每轮回合数提到 32 是唯一让"等"出现过的方向，这与"噪声掩盖信号"
  的解释一致。

**(b) 因此把两个算法侧因子当作一等实验因子放进 v17 组表**（第 6、7 组），
而不是当成既定修复悄悄开着。两者都只是部分有效。

### 一处自己的错误，记在这里

势函数整形的第一版把 Φ(s) 写在了立项循环**之后**，于是本年被立项的地块从
Φ(s) 与 Φ(s′) 里同时被剔除，整形项退化成 (γ−1)Φ 这样一个与择时无关的近似
常数项——"开了整形"而实际上没有任何时序信号，三个种子跑出与未整形档几乎
相同的结果。修正后（Φ 在动作生效前取）才出现上表中 0.967 那一行。
`GateEnv.step` 与 `RenewalEnv.step` 两处都写了注释标明这个坑。

## 2 环境改造：四张逐年变化的机会场（`src/tpmorl/env/opportunity.py`，新增）

逐**单元异步**的非平稳性，四类：

| 场 | 含义 | 通道 | 读哪一年 |
|---|---|---|---|
| `PlanningOpportunity(i,t)` | 上位规划什么时候开始重视这里 | 价值 | **立项年**（申报时点的规划定位决定批得下来多少） |
| `InfrastructureOpportunity(i,t)` | 周边设施什么时候真正成熟 | 价值 | **建成年**（价值在交付时点实现） |
| `BuildingAge(i,t) → 必要性` | 什么时候更新变得越来越必要 | 价值 | 建成年 |
| `ImplementationReadiness(i,t)` | 什么时候真正比较容易做成 | **概率** | 当年 |

前三者相乘构成时机乘子 `M = (1+a_P·P)(1+a_I·I)(1+a_B·N)`，作用在交付建面上。
**相乘而非相加**：三者是同一个项目在不同维度上的"时机好不好"，相加会让任一项
单独变好就足以拉满，相乘要求它们同时到位——这才是"等到规划、设施、必要性都
成熟"的读法。

第四者不走价值通道而走**概率通道**：`hazard_mult = 1 + a_R·(2·ready − 1)`，
调制逐年批准风险率。`ready` 的基期水平取 0.5 使该式在基期恰为 1，故这个参数
改变的是"条件成熟之后更容易批"，而不是整体抬高或压低批准率——不做这个中性化，
`a_R` 会同时改变审批速度的**水平**与**时序**，两个效应无法分离。

### 形状上的三个刻意选择

1. **三型构成**：30% "现在就好"、40% "会变好"、30% "一直不好"。
   **必须有"一直不好"这一型**——若所有地块最终都变好，"一直等"就是最优策略，
   门槛实验会被一个退化解通过，测不出任何择时能力。
2. **逻辑斯蒂爬升而非硬阈值**（时间常数默认 3 年）。外部建议明确要求不要写成
   "30 年以上 = 必须更新"这类硬阈值；机会改善在现实中是逐渐的，硬阈值会把择时
   变成查表。
3. **爬升起始年按决策期 T 的比例给出**（0.15T ~ 0.60T）而非写死年份。
   这样 T=15 与 T=25 两档的场在"相对时序"上可比；写死年份会让 25 年档的场
   全部堆在前三分之一，两档的差异就混进了"场被压缩"这一无关因素。

基础设施场按 (row, col) 聚成片区共享投用年份——地铁开通、道路建成影响的是
一片而不是一个地块。（实现用 nb×nb 等分位网格，nb = ⌈√k⌉，故实际片区数是
nb² 而不是 k；`eff()` 报的是实际值。）

## 3 观测：22 → 30 维（`env_gym.N_FEAT`）

* `22..25` 四个场的**当期水平**
* `26..29` 同四项的**趋势**（t+FORESIGHT 与 t 之差），`FORESIGHT=0` 时为零

趋势那四维不是冗余。门槛实验显示只给当期水平时，策略给所有地块打分用的是
**同一个**函数，"现在一般但会变好"与"一直不好"在观测上无法区分（实测前者的
当期水平甚至更高），于是"留着前者、先做后者"这个最优解根本不在可表示的策略类
里。给未来水平也不够——那只是把同一个贪心排序平移 K 年；**差值**才是"会不会
变好"的直接答案。

这段信息在现实中是有出处的：法定图则、城市更新单元计划、重点片区规划、地铁与
道路建设计划都是提前公布的。`FORESIGHT=0` 档因此不是"更诚实的设定"，而是一个
**信息消融**（第 5 组），用来检验这段信息是不是主判据的载体。

## 4 算法臂：势函数型奖励整形（`env_gym.REWARD_SHAPING`，默认 0）

`F = γ·Φ(s′) − Φ(s)`，`Φ(s) = Σ_{未立项且可立项} φ_u(t)`，
`φ_u(t) = max_{t′∈[t,T-1]} 交付价值(u, 立项于 t′) · γ^{(t′+L_u) − t}`。
`L_u` 用期望时滞（E[离开 S1] + 开工 1 年 + 该单元建设年限），与 slack 特征同
口径。三条必须守住的性质：

1. **不改变最优策略集**（Ng, Harada & Russell 1999），前提是终止态 Φ=0——
   这里由"t ≥ T 后 φ 的取值范围为空、Φ 自然为 0"保证，不需要额外分支。
   这是它可以写进论文的前提：不是把答案喂给策略，而是把同一个最优解的梯度
   变得可跟随。
2. **只进标量奖励，不进 `vec`**。`vec` 是 11 维目标的落盘口径；混进去报出来的
   目标值就不再是目标值。
3. **不入分母缓存键**。参考策略不读整形项，可达上界按构造不变，故整形组与
   主组共用分母、标量化回报可直接相减。

`Φ` 用 `σ==S0 且通道可更新` 判定而**不用** `mask_initiate()`：后者在决策期末
被强制清空，会让 Φ 在 t=T-1→T 之间凭空掉一大块，制造一个与择时无关的虚假信号。

## 5 决策期 15 → 25 年

制度前置期（审批中位 3 年 + 次年开工 + 建设 5 年 = 至少 7 年）把 15 年窗口
砍成前 8 年。按状态机蒙特卡洛重算（`scripts/diag_horizon.py`，2 万次重复）：

| | 期内建成概率 ≈0.70 的立项年 | 结构性死区（必然交付不了） |
|---|---|---|
| T=15 | 第 1–5 年 | 第 10–15 年，占决策期 **40%** |
| T=25 | 第 1–15 年 | 第 20–25 年，占决策期 **24%** |

即"可以真正选时点的年份"从 5 年扩到 15 年，三倍。这是延长决策期的定量依据，
不是"跑久一点看看"。评价期一律 `auto`（T=25 → 36，T=15 → 26），不写死常数。

## 6 择时质量指标（`tpmorl/eval/metrics.timing_quality`）

CRH/LSR 只管"赶不赶得上"，一个把项目尽早塞进管道的策略在这两项上表现最好，
而那恰是 v16 的问题。新增四项管"挑得准不准"：

| 指标 | 定义 | 读法 |
|---|---|---|
| `opp_at_init` | 立项时点上该地块四个场的均值 | 单独看没有尺度，须与下一项一起读 |
| `opp_lift` | 相对"**同一批地块**决策期全部年份"的场均值的提升 | >0 才说明择时有信息。参照系刻意排除选址——否则把"选了哪些地块"与"选在哪一年"混进一个数 |
| `ramp_post_onset` | "会变好"型地块中立项年 ≥ 其爬升起始年的占比 | 必须与 `ramp_post_onset_null`（均匀立项的零假设）同时读 |
| `timing_regret` | 与**单元独立最优时点**的折现价值差距 | 放松了配额与资金冲突，故是**松下界**；只可同口径横比，不可读作"策略还差这么多" |

**在 run 内算，不事后重建**：场依赖（单元数, row/col, 场种子, 形状参数），
事后重建一旦有一处不符就会给出看起来合理却错的数。指标计算用 try 包住——
指标出错不该让一小时的训练白跑，出错时把异常写进 `diag.timing_quality_error`。

## 7 情景参数的接线（`scenario.py`）

全部新参数都做了四件事，缺任何一件都会出现本项目吃过的亏：

1. **snapshot / reset**：漏一项就会静默继承——上一组开着 `a_plan=0.8`、
   这一组没设，实际仍在 0.8 下跑而 `runs.json` 记成 `None`。
2. **取值校验**：负幅度、`a_ready>1`（会让条件差的年份批准率归零，那是行政冻结
   而非难推动）、`share_ramp=0`（没有"会变好"的地块，场退化为平稳场）、
   `onset_lo>onset_hi`、`ramp_years<=0` 全部当场报错。
3. **入分母缓存键**：四个幅度与场的形状参数**都入键**（改变可达上界）。
   观测开关、前瞻年数、整形强度**刻意不入键**（参考策略不读观测与整形项，
   可达上界按构造相同），故这几对组共用分母、标量回报可直接相减。
   本项目已经因为 `FAR_GROWTH` 漏入键栽过一次。
4. **`diag` 记生效值**：记的是 `*_eff` 而不是命令行意图。

## 8 可比性与回归

* **幅度全 0 且整形关闭时，环境动态与 v16 逐位等价**，已机械验证：
  `scripts/verify_opportunity_neutral.py` 用固定种子的动作序列在两版源码上各跑
  一遍，逐年事件 / Floor / Cost / 奖励的 sha 摘要相同（`066724d07d0379ad`）。
  启动脚本每次跑批前重跑一次，不一致即中止整批。
* **网络权重不可跨版载入**：观测 22 → 30 改变了第一层参数量，torch 的初始化
  抽样序列随之改变。与 v15 的 16 → 22 同类，处理方式相同——v17 的结论一律由
  **批次内**对照给出，不与 v16 的图混画。
* 可直接相减标量回报的只有三对：1 vs 2（观测开关）、1 vs 6（每轮回合数）、
  1 vs 7（整形）。

## 9 口径声明（论文必须写）

四个机会场**目前全部是情景参数，没有任何实证标定**。单元表
`zones_v0/candidate_units.csv` 只有 uid / 通道 / 格数 / row / col / 压力 /
距路m 七列，既没有建成年份，也没有历年规划定位或设施投用年份。因此：

* 场的形状（三型构成 + 逻辑斯蒂爬升）是**假设**；
* 场的幅度是情景参数，必须扫（第 8、9 组）；
* 结论只能写成条件句："若上位规划与基础设施按 X 幅度在 Y 年内改善，则最优策略
  呈现 Z 的时序结构"，**不得**写成"实证表明光明区应当推迟某些项目"。

另外，任一幅度 > 0 时 `Floor` 不再是纯粹的计容建筑面积，而是"按时机加权的
交付价值（以建面计量）"，报告时必须写明，不得把加权后的数值当作实测建面。
