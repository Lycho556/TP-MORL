## 1. 准备

```bash
git clone <仓库> && cd TP-MORL
git log -1 --oneline      # 应看到「参考集加入五个定向贪心」或更新的提交
```

环境：`python3.11`、`torch`、`numpy`、`pandas`、`matplotlib`、`scipy`。
数据集随仓库一起来（4.6 MB），**不需要额外传输**。

`git push` 需要服务器上已配好凭据（SSH key 或 credential helper）。
**不要把令牌写进任何文件或命令行**——脚本只调 `git push origin`，凭据由 git 自己取。

## 2. 先干跑一次（约 2 分钟，必做）

```bash
PUSH=0 ITERS=2 EPS=1 BASE=/tmp/dry RES=/tmp/dryres \
    bash scripts/run_batch_v4.sh 1
```

看到 `[35/35]` 与 `成功 1  失败 0` 即通过。然后 `rm -rf /tmp/dry /tmp/dryres`。
干跑不提交、不写进仓库目录，纯粹验证管线。

## 3. 正式跑

```bash
nohup bash scripts/run_batch_v4.sh > results_v4/batch.out 2>&1 &
```

并行度默认取 `核数 − 2`，要指定就 `WORKERS=24 bash ...`。
只跑指定几组：`bash scripts/run_batch_v4.sh 1 2 3`。

**耗时估计**：单组 35 次运行（7 权重档 × 5 种子）× 400 迭代 × 8 回合。
本机 10 并行实测 174 分钟/组，全 6 组约 **17.4 小时**。核多会更快，大致按
`174 × 10 / WORKERS` 分钟/组估。**一夜跑不完 6 组**——脚本每组跑完就推送，
所以早上能拿到前 2–4 组，剩下的接着跑即可。

## 4. 脚本会自动做的事

- 每组先单独预建分母并把**情景键**打进日志（例如
  `B900_C3_G0_V2E1D2Y1-52-53-55-5T15_R4`），事后可核对没有串组
- 跑主扫描，输出到 `data/processed/gm_dataset_v1/exp_v4/<组名>/`
- 刷新 `results_v4/STATUS.md`（进度表）
- `git commit` + `git push origin HEAD:main`，失败自动重试 3 次
- 单组失败**不终止整批**，记为 FAIL 后继续下一组
- 6 组全部成功后：提交「批次 v4 全部实验完成（6/6 组）」并打标签
  `batch-v4-complete` 推到远端 —— **这就是完成标注**

## 5. 跑完后的验收（这一步要你判断，不是脚本能做的）

打开 `data/processed/gm_dataset_v1/exp_v4/base/curves.csv`，对照
`docs/rerun_v2.md` 的基线族表：

| 判定 | 期望 | 不符怎么办 |
|---|---|---|
| α=0 的训练回报 | **应为正**。「不作为吸引子」已消解 | 若 ≤0 属异常，先查分母键是否为 `..._R4`，不要解读前沿 |
| 各档回报 | 应超过该档最优的定向贪心：α≤0.25 看生态定向 **+0.567/+0.405**，α≥0.5 看就业定向 **+0.395/+0.513/+0.617** | 未超过则先查收敛（把 `--iters` 调到 800 跑单点复核），再解读 |
| `small` 类行为的 `Cost` | 非零 | 为 0 说明分母缓存串了，检查日志里的情景键 |

**注意：旧文档里「买最大 +0.358/+0.656」那组数字是 R3 分母下的，已作废，不要拿来对标。**
「买最大」在新分母下任何一档都不再是最优基线。

## 6. 三条必须守住的口径

1. **跨情景的标量化回报不可比**（`curves.csv`、学习曲线、最终回报）——分母按
   情景而异。跨情景只能比 `objectives.csv` 里的 11 维原始量纲值。
2. **不要手工删 `scale_v2/` 下的分母缓存。** 缓存键已含情景参数与参考集版本
   （`_R4`），改了自然不命中；手删只会让脚本重算一遍（8 秒，无害但没必要）。
3. 有 6 组结果就有 6 套分母。把它们并列进同一张表之前，先确认比的是原始量纲值。
