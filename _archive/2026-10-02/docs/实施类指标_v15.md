## 1 为什么要单独做这一层

既有落盘只有两类数字：11 维原始量纲目标值（`objectives.csv`）与标量化折扣回报。
前者答"做出来的东西好不好"，后者答"在这组偏好下得分高不高"。两者都**答不了**
"计划落地了没有"——一个策略可以立一堆项、一个也没建成，目标值却因为 Cost 罚项小
而并不难看。第 6 节给出的实测支持这一担心：`budget1500` 组有一个运行（α=0、
seed=2）在 5 个回合里**一个项目都没立**，目标层照样给它一组分数。

## 2 完工年是怎么来的（关键口径，必读）

`rec_a*_s*.csv` 只记**立项事件**，列为 `ep, year, unit, channel, target, n_cells,
cost, budget_before, spent, stopped`，**没有完工年、没有终态**。按本轮分工不得改动
`env_gym.py` / `train_ppo.py` 去补日志，所以完工年只能从状态机推。

这件事能**精确**推出来，靠的是一个结构性事实：立项之后的轨迹**完全外生**。
`env_gym.step()` 里写的是 `advance=np.where(ma)[0]`——每年把**全部** S1 单元都推进
一次，agent 在立项之后再没有任何选择权。于是给定立项年 `y`、该单元建设年限 `b`，
以及 `(hazard, tau_max)`，交付时点只由一个随机量决定：获批发生在第几个有效年 `k`。

按 `schedule.RenewalSchedule.step()` 的真实执行顺序（冷却释放 → S3→S4 → S2→S3 →
推进 → 倒计时/失效 → 立项 → clock 自增）推导：

| 量 | 表达式 |
|---|---|
| 获批年 | `t_a = y + 1 + k`，`k = 0 … tau_max-1` |
| 完工年 | `t_c = t_a + 1 + b = y + k + b + 2` |
| 失效年 | `t_x = y + tau_max`（`k` 全部落空） |
| `P(k)` | `(∏_{j<k}(1-h_j)) · h_k` |
| `P(失效)` | `∏_{j<tau_max}(1-h_j)`，默认档 = **0.294** |

`hazard` 下标按 `schedule` 的做法钳到 `len(hazard)-1`，故 `tau_max` 可大于
`len(HAZARD)`。

### 2.1 这三条式子的验证（实际跑过）

用 `RenewalSchedule` 逐步模拟，单元在第 `y0=2` 年立项、`b=5`、4000 个随机种子：

| 检验项 | 结果 |
|---|---|
| 完工者 `t_c - (y0+k+b+2)` 是否恒为 0 | **True**（4000/4000 逐位相等） |
| 失效年取值集合 | `{7}`，与 `y0+tau_max = 2+5 = 7` 一致 |
| `P(k)` 解析 | `0.1740, 0.1751, 0.1556, 0.1372, 0.0641` |
| `P(k)` 实测 | `0.1680, 0.1713, 0.1552, 0.1505, 0.0632` |
| `P(失效)` 解析 / 实测 | `0.2940 / 0.2918` |

前两条是确定性关系，逐位精确；后两条是蒙特卡洛，差异在 4000 样本的抽样误差内
（各档实测之和 0.7082 与 `1-0.2918` 逐位相等）。

### 2.2 这是期望口径，不是那一次的实现

据此，本模块把每个真实发生的立项事件展开成 `tau_max+1` 个带概率权重的结局，
再做加权统计。**这不是蒙特卡洛近似，而是对同一状态机的解析积分**：方差为零、
可复算，且与 `objectives.csv` 里那一次随机抽样同分布。

代价必须写明：它**不反映该次运行实际抽到的 hazard 序列**。因此不应期待它与
`objectives.csv` 中依赖具体实现的量（如 `Expire` 罚项）逐位相等，只应同向
（第 6.4 节给出实测的同向性）。

作为端到端核对，另把 `rec` 记录的立项年**重放**进 `RenewalSchedule`
（每文件 50 次重放，每组取前 8 个文件、`ep==0`）：

| 组 | CRH 解析 / 重放 | ACD 解析 / 重放 | 失效率 解析 / 重放 |
|---|---|---|---|
| carry1 | 0.2948 / 0.2984 | 8.371 / 8.412 | 0.1968 / 0.1922 |
| carry3 | 0.3211 / 0.3171 | 8.394 / 8.393 | 0.2007 / 0.2042 |
| carryInf | 0.3081 / 0.3091 | 8.373 / 8.389 | 0.1971 / 0.1946 |
| budget1500 | 0.3112 / 0.3090 | 8.390 / 8.407 | 0.1991 / 0.2068 |

（此处"解析"值按同一子集算，故与第 6 节的池化值不同；两列可直接对比。）
CRH 差 ≤ 0.004、ACD 差 ≤ 0.04 年、失效率差 ≤ 0.008，均在重放的抽样误差内。

## 3 两个时间口径（本项目踩过的坑）

决策期 `T` 与评价期 `T_eval` 是两个不同口径：`T_eval > T` 时，第 `T` 年起不再立项、
不再进钱，只推进状态机并结算建成年释放的目标。环境在 `t >= T_eval` 结束，故实际
执行的最后一步是 `t = T_eval - 1`。"期内完工"的判据因此是

- 以 `T` 为界：`t_c <= T - 1` → **`CRH_T`**
- 以 `T_eval` 为界：`t_c <= T_eval - 1` → **`CRH_Teval`**

两者含义不同，混用会得出相反结论，所以 CRH **必须同时给出并分别命名**。
由 `T-1 <= T_eval-1`，恒有 **`CRH_Teval >= CRH_T`**——这是实现自检的硬条件（第 7 节）。

### exp_v12 为什么两者相等

`exp_v12` 是**闭区间口径**跑出来的（`T_eval == T == 15`，见 `runs.json` 的
`config.horizon`，该批次的 `diag` 还没有 `t_eval_eff` 字段，故由 `config` 兜底，
`实施类指标_分组.csv` 的 `T来源` 列记为 `config`）。此时两个界完全相同，
`CRH_Teval` **必然等于** `CRH_T`。**这不是 bug。**

新批次 `T_eval = 26` 下两者才会分开。把同一批 `rec` 的完工判据时间界改成 26
（`--T-eval 26`，纯口径演示，**不是** v15 的真实结果）：

| 组 | `CRH_T` | `CRH_Teval`（界=15） | `CRH_Teval`（界=26，演示） |
|---|---|---|---|
| carry1 | 0.2824 | 0.2824 | 0.7060 |
| carry3 | 0.3036 | 0.3036 | 0.7060 |
| carryInf | 0.2998 | 0.2998 | 0.7060 |
| budget1500 | 0.3047 | 0.3047 | 0.7060 |

演示值四组全等于 0.7060 = `1 - 0.294`，因为 26 年足够长：最晚的立项（`y=14`）
最迟也在 `14+4+5+2 = 25 <= 25` 完工，于是**只有失效才不完工**，CRH 退化成
`1 - P(失效)`，对立项时点完全不敏感。这说明 `T_eval` 取得过长会让 CRH 失去分辨力：
`T_eval = 26` 对 `T = 15` 的决策期而言已经"太宽容"，横比时应以 `CRH_T` 为主判据、
`CRH_Teval` 作补充。

## 4 slack 与 LSR 的口径

LSR（窗外立项率）= 立项时 `slack < 0` 的单元占全部立项的比例。`slack` 复用
`schedule.expected_years_to_delivery(if_initiated_now=True)` 的**期望**定义：

```
ey    = E[离开S1] + 1(开工) + b
slack = (T - 1 - y) - ey
```

与 `env_gym.obs()` 里 `F[:,19]` 的 slack 特征**逐字同式**（同样用 `T-1`、同样用 `T`
而非 `T_eval`），即"策略当时看到的可交付性判断"。

**这是期望口径，不是乐观口径**——`E[离开S1]` 按 `E[v] = 1 + (1-h_v)·E[v+1]`、
`E[tau_max-1] = 1` 反向递推，把"失效"也计为离开，实测默认档 `E[0] = 3.3303` 年
（`schedule` 文档记的 3.33）。用乐观口径（假设次年必获批，即 `E[0]=1`）会系统性
**高估**可交付性，策略据此在窗外立项，而这正是本项目要诊断的行为，故不采用。

默认档下 `b = 5`（`BUILD_YEARS_BY_CHANNEL` 四个可更新通道一律 5），于是

```
ey = 3.3303 + 1 + 5 = 9.3303
slack < 0  ⟺  14 - y < 9.3303  ⟺  y > 4.6697  ⟺  y >= 5（0 起年号）
```

即"第 6 年及以后立项"（1 起年号）。

## 5 失效率与资金闲置率的重算口径

**失效率**（S5 占立项数）分三个版本：

- `expire_rate_uncond = ∏(1-h_j)`，**与立项年无关**，默认档恒为 0.294。
  它只由 `hazard × tau_max` 决定，反映制度参数，不反映策略。
- `expire_rate_T` / `expire_rate_Teval`：要求 `t_x = y + tau_max` 落在界内
  （`<= T-1` / `<= T_eval-1`）。**只有带截断的版本才反映择时**——临界前立项的单元
  来不及在期内走完 5 个有效年，其失效不计入，故带截断值恒 ≤ 无截断值。

**资金闲置率** `= 1 - 累计支出 / 累计到账`，累计到账取 `budget × T ×回合数`。
口径依据（`env_gym.step`）：`t=0` 年初已到账一笔 `BUDGET`，此后每步末再到账一笔，
但**尾部评价年不进钱**，且第 `T-1` 步末到账的那笔在决策期结束后已无处可花。故
"决策期内可动用的到账总额" = 初始 1 笔 + 决策期内 `T-1` 笔续拨 = `budget × T`。
分子取 `rec` 中 `unit >= 0` 行的 `cost` 之和，即立项承诺全额（与 upfront 口径下的
`Cost` 目标同口径；staged 模式下承诺总额与支付总额相等，仅年内分布不同）。

这一分母与既有判据 `diag.spend_ratio` 一致，故可逐位对照（第 6.4 节）。

附带的分解（诊断用，非主判据，分母同取 `budget × T`）：

- `clipped_ratio`：因超结转上限 `carry_cap × budget` 被截断而**作废**的额度占比。
  这部分不是"闲置"（想花也花不出去），必须与余额区分开。
- `residual_ratio`：期末仍挂在可承诺额度上的余额占比。
- `decomp_sum = spend + clipped + residual`，恒等值是 **`(T+1)/T`，不是 1**。
  这是口径而非误差：资金实际到账 `T+1` 笔（年初 1 笔 + 决策期内每步末各 1 笔共 `T`
  笔），换算成绝对金额则严格闭合：`支出 + 作废 + 期末余额 == budget × (T+1)`。
  分母取 `budget × T` 是为了与 `diag.spend_ratio` 对齐，代价就是三项之和为 `(T+1)/T`。
  四组实测 `decomp_sum = 1.066667 == 16/15`，与此式逐位一致；代码里已加 `assert`，
  不闭合会直接报错。

## 6 exp_v12 四个干净组的实测指标

用 `carry1 / carry3 / carryInf / budget1500`。另三组（`carry6 / budget600 / loose`）
因容积率动力学污染已作废，`scripts/eval_metrics.py` 把它们写进 `TAINTED_V12` 并
**默认拒绝统计**（实测：传 `--groups carry6` 直接报错退出，须显式加
`--allow-tainted`）。

每组 35 个运行（7 个 α × 5 个种子）× 每运行 5 个回合 = 175 个回合。分组值是把全部
运行的立项事件**池化**后重算，不是对逐运行指标取均值——比率的均值不等于池化比率
（各运行立项数不同），池化才是"该组的落地程度"。

### 6.1 规模与 CRH / ACD

| 组 | 立项事件数 | 每回合立项数 | `CRH_T` | `CRH_Teval` | `ACD_T` | p25 | p50 | p75 |
|---|---|---|---|---|---|---|---|---|
| carry1 | 4050 | 23.14 | 0.2824 | 0.2824 | 8.364 | 7 | 8 | 9 |
| carry3 | 4430 | 25.31 | 0.3036 | 0.3036 | 8.382 | 7 | 8 | 9 |
| carryInf | 5005 | 28.60 | 0.2998 | 0.2998 | 8.378 | 7 | 8 | 9 |
| budget1500 | 6290 | 35.94 | 0.3047 | 0.3047 | 8.376 | 7 | 8 | 9 |

四组的 `CRH_T` 都在 0.28–0.31：**立项十个，期内建成不到三个**。

**ACD 的右尾截断偏差（必须写明）**：ACD 只对该口径下**已完工**单元计。未在界内完工
者——包括全部失效单元（`P=0.294`）与立项过晚来不及建成者——一律不计入。这两类恰恰
是交付时长最长的，被剔除后右尾被**截断**，故 ACD 系统性**偏小**，只能同口径横比，
不能解读为"从立项到建成平均 8.4 年"。分布本身也是右偏的：p25=7、p50=8、p75=9，
均值 8.36–8.38 落在 p50 与 p75 之间。四组 ACD 差异在 0.02 年内，说明 ACD 对情景
几乎不敏感——它主要由 `hazard × b` 决定，不是区分策略的好指标。

### 6.2 LSR、失效率

| 组 | `LSR` | `slack` 均值 | 第 6 年及以后立项占比 | 第 7 年及以后 | `expire_rate_T` | `expire_rate_uncond` |
|---|---|---|---|---|---|---|
| carry1 | 0.6864 | -2.553 | 0.6864 | 0.6296 | 0.1898 | 0.294 |
| carry3 | 0.6591 | -2.287 | 0.6591 | 0.5959 | 0.1968 | 0.294 |
| carryInf | 0.6633 | -2.361 | 0.6633 | 0.5994 | 0.1942 | 0.294 |
| budget1500 | 0.6598 | -2.249 | 0.6598 | 0.5914 | 0.1977 | 0.294 |

**三分之二的立项发生在期望上已经交付不了的时点**（LSR 0.659–0.686），
`slack` 均值 -2.2 到 -2.6 年。带截断失效率 0.190–0.198，远低于无截断的 0.294，

### 6.3 资金口径

| 组 | `budget` | `carry_cap` | `spend_ratio` | `idle_ratio` | `clipped_ratio` | `residual_ratio` | `decomp_sum` |
|---|---|---|---|---|---|---|---|
| carry1 | 900 | 1 | 0.964720 | 0.035280 | 0.035280 | 0.066667 | 1.066667 |
| carry3 | 900 | 3 | 0.974984 | 0.025016 | 0.015090 | 0.076593 | 1.066667 |
| carryInf | 900 | 999 | 0.997640 | 0.002360 | 0.000000 | 0.069026 | 1.066667 |

"额度给多了花不掉"误读成"想花没花"。

## 7 两条硬自查的实际结果

`自查结果.csv`，逐组：

**自查 1：`CRH_Teval >= CRH_T`。** 四组全部通过，`自查1_CRH单调_违例运行数` 在
140 个运行上均为 **0**。由于 `exp_v12` 是闭区间口径，实际取等号（第 3 节已说明
这不是 bug）。

**自查 2：LSR 与"第 6 年及以后立项占比"同向。** 四组 LSR 实测
**0.6864 / 0.6591 / 0.6633 / 0.6598**，即 **65.9%–68.6%**，与任务给出的
"四个干净组实测 65.9%–68.6%（加过滤后）"**逐位吻合**；逐运行 Pearson r = 1.0，
四组全部同向。

**但这条自查的强度必须说清楚，否则会被误读成独立验证。** 第 4 节推导给出
`slack < 0 ⟺ y >= 5`，而默认档下四个可更新通道的 `b` 一律为 5，于是 `ey` 逐单元
相同，LSR 与"第 6 年及以后立项占比"在本批次里是**恒等关系**——实测 140 个运行上
`|LSR - late_share_y5|` 最大值 `< 1e-12`，相关系数 1.0 是恒等的结果，不是独立证据。

所以这条自查真正验证的是：**slack 公式的阈值落在了推导预言的那一年（第 6 年）**，
且 `unit >= 0` 过滤生效（未过滤会把 `unit=-1` 的闲置年占位行算成立项；四组分别有
40 / 45 / 5 / 105 行这类占位行）。一旦 `BUILD_YEARS_BY_CHANNEL` 真正分档
（通道间 `b` 不同），两者就会分开，那时这条自查才成为独立的一致性检验。

## 8 三层评价指标表

落盘 `三层评价指标表.csv`，18 行（11 个目标层 + 6 个实施层 + 1 个标量层），
列为 `层 / 指标 / 定义 / 时间口径 / 数据来源 / 可跨情景比 / 备注`。每行都写明该指标
从**哪个落盘文件的哪一列**算出。摘要：

| 层 | 指标 | 数据来源 | 可跨情景比 |
|---|---|---|---|
| 一 目标层 | 11 维原始量纲目标值（Gdp/Eco/Res/Emp/Aec/E2r/Cpt/Floor/Cost/Disrupt/Expire） | `objectives.csv` 对应列 | **是** |
| 二 实施层 | `CRH_T` | `rec_a*_s*.csv` 列 `unit`(>=0 过滤)/`year`/`channel` + 情景参数，按 `t_c=y0+k+b+2` 展开 | **是** |
| 二 实施层 | `CRH_Teval` | 同上，完工判据时间界改为 `T_eval-1` | **是** |
| 二 实施层 | `ACD`（含 p25/p50/p75） | `rec_a*_s*.csv` 列 `year`/`channel` + 情景参数，`duration=t_c-y0` | **是** |
| 二 实施层 | `LSR` | `rec_a*_s*.csv` 列 `year`/`channel` + 情景参数；`ey` 复用 `expected_years_to_delivery(if_initiated_now=True)` | **是** |
| 二 实施层 | 失效率 | `rec_a*_s*.csv` 列 `year`(>=0 过滤) + `hazard`/`tau_max` | **是** |
| 二 实施层 | 资金闲置率 | 分子 `rec_a*_s*.csv` 列 `cost`(>=0 过滤) 求和；分母 `runs.json` 的 `config.budget × config.horizon` | **是** |
| 三 标量层 | 标量化折扣回报 | `runs.json` 的 `runs[*].curve` 尾段（`curves.csv` 同源）；分母来自 `rl/scale.py` 的参考策略集 | **否** |

**为什么实施层可跨情景比**：CRH / ACD / LSR / 失效率 / 资金闲置率全是以**本组自身**
的立项数或到账预算为分母的比率，分母里不含参考策略集、不含可达上界，换情景只换被
统计的行，不换刻度。

**为什么标量层不可跨情景比**：分母 `scale` 取参考策略集的可达上界，而
`quota / hazard / budget_mode` 等均已进 `scenario.inst_tag()` 缓存键——换情景即换
分母，数值不同量纲。跨情景只能比目标层与实施层。

**实施层内部也有横比限制**（补充，不在 csv 主判据里）：`ACD` 因右尾截断只能同口径
比；`CRH_Teval` 在 `T_eval` 取得过长时退化为 `1-P(失效)`（第 3 节实测 0.7060），
失去分辨力。

---

## 9 结论：这些指标能不能把"落地程度"与"目标得分"区分开

**能。** 组内按 `(组, α)` 分层（跨情景分母不同、跨 α 权重不同，直接混算会把口径差异
当成相关性）后，实施层与标量层折扣回报的分层平均相关系数（Fisher z 平均后回变，
28 层、每层 5 个种子，最小层 4 个）：

| 实施层指标 | 与标量层折扣回报的组内分层平均 r |
|---|---|
| `CRH_T` | **-0.053** |
| `LSR` | **+0.051** |
| `expire_rate_T` | **-0.217** |
| `idle_ratio` | **+0.124** |

四项都接近 0：**在同一情景、同一偏好下，标量化回报高的运行并不更"落得了地"**，
实施层携带了标量层没有的信息，不是它的冗余重述。最直接的一例是
`budget1500 / α=0 / seed=2`：5 个回合里**一个项目都没立**，目标层与标量层照样给出
一组分数，而实施层的比率指标在该运行上是 `0/0`（落盘为 NaN）——"什么都没做"这件事
只有实施层报得出来。

两点限制要一并写明：(1) 每层只有 4–5 个种子，单层相关系数噪声大，上表是 28 层
汇总后的值，只支持"接近 0"这一定性结论，不支持给出置信区间；(2) 本节的实施层数值
是**期望口径**（第 2.2 节），与标量回报所依赖的那一次随机实现不是同一抽样，
这会使相关系数向 0 偏——故"接近 0"这一结论是**保守**方向的，但其绝对强度不宜外推。

## 10 复算命令

```bash
export PYTHONPATH=src
python scripts/eval_metrics.py \
    --batch data/processed/gm_dataset_v1/exp_v12 \
    --groups carry1,carry3,carryInf,budget1500 \
    --out data/processed/gm_dataset_v1/eval_v15
```

`--groups` 留空则自动取全部组并自动剔除 `TAINTED_V12`。情景参数优先取
`runs.json` 里 `runs[*].diag` 记录的**实际生效值**（`t_dec_eff` / `t_eval_eff` /
`budget_eff` / `carry_eff`），其次才回落到 `config` 的意图值，落盘时把来源写进
`T来源` / `budget来源` 等列——v12 有三组因分母构建泄漏 `FAR_GROWTH`，意图值与实际
运行不符，教训是凡有 `*_eff` 就用 `*_eff`。`--T` / `--T-eval` / `--tau-max` 可覆盖
（用于第 3 节的口径演示，日常统计不要用）。
