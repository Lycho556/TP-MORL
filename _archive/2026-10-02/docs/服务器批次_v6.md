## 与 v5 的差异

1. **失效后改为规划期内吸收态**（S5 不再返回 S0）作主设定。原"冷却 2 年"降为宽松
   对照。`schedule.COOLDOWN` 默认 `inf`
2. 冷却期敏感性方向由 `{0,1,2,3}` 改为 `{吸收态, 2, 5, 0}`，0 档仅作最宽松极端参照
3. `REF_VER` R5→R6，分母全部重建。**R5 分母不可复用**
4. `--cooldown` 由 int 改为 str，接受 `absorb`

## 跑法

```bash
cd TP-MORL && git pull
bash scripts/run_batch_v6.sh          # 全六组；也可 bash scripts/run_batch_v6.sh 1 3
```

预计与 v4 同量级（128 核约 4 小时）。完成后打 `batch-v6-complete`。

## 服务器可自查的三条

1. 六组日志里的分母缓存键必须**互不相同**，且第 1 组含 `DA`、第 2 组含 `D2`：
   `grep -h 分母 results_v6/g*.log`
2. 全部键必须以 `_R6.csv` 结尾。出现 `_R5` 说明 `git pull` 没生效
3. 第 1 组与第 2 组的 `objectives.csv` **必须不同**（吸收态确实改变了动力学）；
   逐位相同即为改动未生效，停下来报回

## 已知且不需报的现象

八个正向目标的**分母数值在 base/relax2/relax5 三组间相同**。已逐行核对：45 条参考
策略里 34 条数值不同，只是取到最大值的那条策略从不让计划失效、不受冷却期影响，
差异落在 `Disrupt` 与 `Expire` 列。不是缓存串组。
